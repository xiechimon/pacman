### 1.5 客户端状态存储（实测 `localStorage` 键名，直接可作复刻契约）

```
tds-theme                       light | dark
tds.locale / tds-locale         zh
tds.sidebarProjectsCollapsed    "1"
tds.panel-maximized             "0"
tds.teamMembersLayout           grid | chart      （团队页视图切换，实测点 chart 后持久化）
tds.cache.session-v1            {token:"",cookieName:"",expiresAt,user{...}}   → 会话走 cookie，token 字段留空
tds.cache.me-v1:<userId>        {type:"user",id,displayName,avatarUrl,...}
tds.cache.teams-v1:<userId>     [{id,name,createdAt,plan:"free",avatarStyle:"notionist..."}]
tds.cache.members-v1:<userId>:<teamId>   [{id,teamId,actorId,memberType:"user",r...}]
tds.cache.projects-v1:<userId>:<teamId>  []
tds.cache.team-models-v1:<teamId>        {"models":[]}
tds.cache.team-machines-v1:<teamId>      []
tds.cache.progress-v2:<userId>:<teamId>  {"todos":[],"builds":[]}
tds.cache.notifications-v2:<userId>:<teamId> {"unreadThreadIds":[]}
tds.cache.chief-data-v3:<userId>:<teamId>     {"chief":{id:"chief-<user>-<team>",userId,teamId,...}}
tds.cache.chief-threads-v1:<userId>:<teamId>  []
nextauth.message                {"event":"session","data":{"trigger":"getSession"}}
mixpanel: mp_* / __mpq_*        （埋点，distinct_id = userId）
```

要点（均为实测键名/值）：
- 缓存命名规范 `tds.cache.<entity>-v<N>:<scope…>`，scope 为 userId / teamId 组合 → **cache-first + 版本化 + 多租户分片**。
- 总管（chief）是**每用户×每团队一个实例**：`chief-<userId>-<teamId>`，会话列表独立存 `chief-threads-v1`。
- `plan` 字段挂在 team 上（值 `free`），不是挂在 user 上。
- 后端鉴权为 cookie 会话（`session-v1.token` 为空串）。
- 前端框架线索：DOM class 为原子化 RNW 风格（实测 `css-g5y9jx r-150rngu r-18u37iz r-16y2uox …`、`r-1loqt21`（cursor:pointer）、`css-146c3p1`）→ **[推断] Web 端由 React Native Web / Expo 系构建**。

## 5. 核心对象：任务（todo）生命周期

### 5.1 实测生命周期边界

```
创建（+ 任务 → 保存任务）→ 卡片落「待开始」列，面板状态芯片 = 待处理
   → 点「开始」→ 被门控弹窗拦截：团队需要「一台可运行的机器」+「一个可用的模型」
   → free 档两项均未配置 → 无法进入 规划中 / 待确认 / 执行中 / 待验收 / 已完成
```

因此以下界面 **未配置-未见**（free 账号在本盘点中不可达）：plan 卡与 plan 确认交互、执行流 transcript / 工具活动、token 记账数值、验收界面、完成态。这些屏的文案锚点只能从门控弹窗与空态文案反推（§7.2、§4.1）。
