# 13 · 资源面本地化：skills 与 MCP 只读本地

> 决策来源 = 2026-09-28 grilling 会话（Q1–Q8 全钉死）。本 spec 锁 skills / MCP 两条资源面的终态：来源从「DB 登记制」改为「本地文件只读制」，DB 两表与配套管理面全删。父 issue = #365；施工票 #367（T1 skills 本地面）/ #368（T2 MCP 本地面）无 blocking 边，可并行。
>
> 本地正本：skills 目录默认 `~/.agents/skills`；MCP 配置默认 `~/.claude.json` 的 `mcpServers` 段。

## Problem Statement

skills 与 MCP 现状都是「登记进 pacman DB」模型，四个痛点：

1. **重复登记**：用户本机已有维护好的 skills 目录（`~/.agents/skills`）与 MCP 配置（`~/.claude.json`），pacman 要求在 UI 里重新登记一遍才有。
2. **双真相漂移**：本地目录改了 DB 不知道；`~/.claude.json` 改了 DB 不知道。DB 行是迟早过期的副本。
3. **GitHub 扫描面是 self-host 负担**：`scanGithubSkills` 依赖出站 REST（未认证 60 req/h 限流），对「技能就在磁盘上」的单用户场景是纯复杂度。
4. **凭证面过宽**：MCP headers 密钥经 SecretBox 落 server DB、再 per-step 跨 server→daemon wire 下发——而 daemon 本机 config 里明明就有原文。

## Solution

两条资源面统一改为**本地文件只读制**：

- **skills**：server 现扫本地目录（默认 `~/.agents/skills`，可配），每个含 `SKILL.md` 的子目录 = 一个技能；**id = 目录名**。不入库、无导入页、无 GitHub 扫描。
- **MCP**：读 `~/.claude.json` 的 `mcpServers` 段。UI 展示由 **server 读本机** config；任务执行由 **daemon 读本机** config 自行解析端点——stdio 命令在真正的执行机上起，语义随机器正确。密钥从此不落地 DB、不跨 wire。
- **删除面**（No Negative Echo，废路径残骸全清）：`skill` 表、`mcp_server` 表、skills 导入页、MCP 新建/编辑管理写面、GitHub 扫描服务、chief `delete_skills` 工具、对应 REST 写端点。
- **保留面**：agent 行的 `skills[]` / `mcpServers[]` 授权勾选语义不变，值语义从「DB id」改为「目录名 / config 键名」；现有 wire record 形状（`SkillRecord` / `McpServerRecord`）保留以收窄 web 改动面。

## User Stories

1. 作为 self-host 用户，我把一个含 SKILL.md 的目录放进 `~/.agents/skills/`，刷新 pacman 技能页就能看到它——没有任何「导入」动作。
2. 作为 Claude Code 用户，我在 `~/.claude.json` 里配好的 MCP server 直接出现在 pacman 的 MCP 页与 agent 勾选列表里——零重新登记。
3. 作为安全审阅者，我看 MCP 的 env/headers 密钥只存在于 daemon 本机 config 文件，server DB 无副本、server→daemon wire 只传 slug 列表、UI 接口只暴露 `hasCredential`/`credentialKeys` 投影。
4. 作为多机用户，我的远端 daemon 读的是**远端那台机器**的 `~/.claude.json`——server 机器上的 stdio 命令不会被拿到远端误执行。
5. 作为维护者，我删掉 `~/.agents/skills/foo/` 目录，技能页下一次刷新就不再有 `foo`；引用过它的 agent 行在下次执行时按「未知技能跳过」容忍，不炸任务。
6. 作为旧版升级用户，我升级后 DB 里的旧 skill/mcp_server 行已被导出到 `~/.pacman/legacy-export-<ts>.json`，agent 行上失效的旧 id 被清空，我重新勾选一次即可。
7. 作为 UI 用户，技能页与 MCP 页都不再出现「新建/导入」按钮——页面的空态文案告诉我去哪个目录/哪个文件加配置。
8. 作为回归测试者，技能页与 MCP 页的 e2e 钉扎从「可点新建」翻转为「无新建入口 + 列表来自本地源」，verify-pacman feature map 同步更新。

## Implementation Decisions

### 模块改动清单（决策点，不含具体文件路径）

**shared**
- `SkillRecord` wire 形状保留（id/teamId/name/description），`id` 语义 = 目录名，`teamId` 填当前 team 占位（收窄 web 改动面）。
- `McpServerRecord` wire 形状保留；stdio 条目的 `url` 槽位现填 command 预览的现状（mapMcpServers 已如此消费）保持。
- **machine-wire 断约**：claim 载荷的 `mcpServers` 字段从 `McpEndpoint[]`（server 解析好的端点）改为 `string[]`（slug 列表，daemon 自行解析）。版本墙常量提升——旧 daemon 不再收到 MCP 配置（视为无 MCP 运行），不混发两种形状。

**server**
- skills 服务重写为本地目录扫描：`readdirSync` 一级子目录 + 每个子目录查 `SKILL.md` + 复用现有 frontmatter 最小解析器（name/description，折叠块标量回落不变）。目录不存在 = 空集（不炸）。
- 新增 claude.json 读取缝：读 `~/.claude.json` 的 `mcpServers` 段 → 逐条 zod 校验（stdio: command/args/env；http: url/headers）→ 坏条目跳过不炸全局 → 投影 `McpServerRecord[]`（**env/headers 的值不出 server**，只投影 `hasCredential`/`credentialKeys`）。文件不存在/坏 JSON/无 mcpServers 键 = 空集。
- `GET /api/skills?teamId=` 与 `GET /api/teams/{id}/mcp-servers` 读端点换源（上述两缝）；skills 的 POST/scan 端点、mcp-servers 的 POST/PATCH/DELETE 端点全删。
- drizzle migration 一条：`DROP TABLE skill`、`DROP TABLE mcp_server`；同 migration 内导出两表现存行到 `~/.pacman/legacy-export-<ts>.json`（升级护栏），并把 agent 表的 `skills`/`mcpServers` 两列清为 `'[]'`（旧 id 随表失效，死引用不留）。票面不写死 migration 编号，合并期按 main 尾部 + 1 编。
- chief-tools：`skills` / `mcp_servers` 读面换源；`delete_skills` 工具删；create agent 默认 `skills: []`/`mcpServers: []` 不变。mcp-face 的 `skills` 读面换源。
- agent 行 `skills[]`/`mcpServers[]` 的校验从「DB 存在性」改为「本地源存在性」，未知项容忍跳过（与现 resolveAgentMcpEndpoints 的 slug 未知跳过同律）。

**web**
- 技能页：删「新建技能」钮与 `/import` 路由整页（含文件夹上传/GitHub 双 tab、chief 提示文案）；空态文案改为「把含 SKILL.md 的目录放进 <目录路径> 即出现在这里」。
- MCP 页：删新建/编辑入口（CreateMcpDialog 与行内编辑），行改只读；空态文案指向 `~/.claude.json`。
- agent 编辑面：skills/MCP 勾选候选集改从两个读端点拉（数据源换，控件不动）。
- mention picker 的技能组：候选源随读端点换源，id = 目录名。
- i18n en/zh 同步（删导入页文案、增两条空态文案）。

**daemon**
- config 增 `mcpConfigPath`（默认 `~/.claude.json`，env 可覆盖）。
- runner：claimed 载荷的 `mcpServers` 现为 slug 列表 → daemon 读本机 config 解析出 `McpEndpoint[]` → 喂既有 `connectMcpBridge`（桥本身零改动）。未知 slug / 坏条目跳过，canon 降级行 `[mcp] <slug>: ...` 族扩展一行「config 里找不到」。
- **skills 无 daemon 面**：daemon 源码对 skills 零消费（2026-09-28 实测 grep 零命中），本 spec 不改变这一点——skills 的执行面注入归后票。

**verify / e2e**
- verify-pacman feature map：技能页/MCP 页两条改「只读列表 + 无新建入口」断言。
- e2e：技能页无 `res-new` 钮、无 `/import` 路由可达；MCP 页无新建钮；agent 编辑面勾选候选 = fixture 化的本地源。
- fixture 面：skills/MCP fixture 数据改为模拟「本地源投影」，页面渲染逻辑不变。

### 数据契约（票内可微调）

- `GET /api/skills?teamId=` → `SkillRecord[]`（`id` = 目录名；现扫，无缓存）
- `GET /api/teams/{id}/mcp-servers` → `McpServerRecord[]`（config 投影；env/headers 仅键名）
- machine-wire claim：`mcpServers?: string[]`（slug 列表；版本墙常量提升，旧 daemon 收不到此字段）
- 配置文件 schema（消费面，非 pacman 所有）：`~/.claude.json` → `{ mcpServers: { <slug>: { command?, args?, env?, url?, headers? } } }`

## Testing Decisions

测试侧重端到端与边界行为，不校验实现细节。

- **server 集成测**：目录扫描六态（目录不存在 / 空目录 / 无 SKILL.md 子目录 / 嵌套技能 / 折叠 frontmatter 回落 / 正常多技能）；claude.json 解析五态（文件不存在 / 坏 JSON / 无 mcpServers 键 / 单条坏条目跳过 / http+stdio 混合正常）；投影面断言 env/headers 值不出接口。
- **migration 测试**：构造含行的旧库 → migrate → 两表不存在、legacy-export 文件落盘内容齐、agent 两列空。
- **daemon 单测**：slug → config 解析（正常 / 未知 slug 跳过 / 坏条目跳过）；`mcpConfigPath` env 覆盖。
- **web e2e**：技能页无新建入口 + 列表渲染本地源；MCP 页同；agent 编辑面勾选候选与本地源一致；旧路由 `/app/resources/skills/import` 404 或重定向。
- **版本墙**：旧 latestCliVersion 的 machine 行 claim 载荷不含 mcpServers 字段。

## Out of Scope

- **skills 执行面注入**（把技能内容喂给 worker/chief 会话）：daemon 现状零消费，本 spec 不动；S2 起进 scope（见下方「写路径回摆」）。
- **第二 config 源合并**（如 pacman 专属 `mcp.json` 与 claude.json 并存）：单源先行，合并语义归后票。
- **多技能目录**：可配但只有一个目录槽；多目录扫描归后票。
- **技能删除面**：删除 = 从磁盘删目录（用户自己动手），server 无删除端点；delete_skills 维持除名。

### 写路径回摆（XMON-109，2026-10-01）

原 Out of Scope 两件移入 scope，技能库从「只读投影」回摆为「单目录读写」：

- **网页/relay 建技能与更新技能**：`POST /api/skills`（member）+ `PUT /api/teams/{id}/skills/{sid}`（覆写语义：列出者覆写、未列者保留）+ worker relay `create_skill`/`update_skill`（词表恒列，agent 行「创建技能/更新技能」开关执法，403 同 requestMerge 形）。body `{name, description, files: [{path, content}]}`；frontmatter 是唯一真值（name/description 必填且须与 body 声明一致；改名 = 携带新 SKILL.md，目录不动、id 随 frontmatter 走）。校验闸：目录名安全域、路径守卫（拒逃逸/拒穿符号链接写）、单文件 512k / 单技能总量 2M 字节、目录占用或撞 id 409、未知 id 404。双入口双动作均落 `skill_audit` 审计行（REST + relay 同表，actor_type = member|agent）。
- **chief 自动制作技能**：chief 词表增 `create_skill`/`update_skill`（organize 位，CHIEF_TOOLS_ADDED 登记），免 agent 行开关（chief = 信任面）。
- **machine-wire 技能包下发**：`GET /api/machine/skills/{stepId}`（[设计] 附加端点，MACHINE_WIRE_EXTENSIONS 登记）——S2 daemon 物化消费契约：worker 步按该步 agent 的 skills 白名单交集出包（chief 步 = 信任面全量），含 dirName 与全文件内容，字节闸同写面。执行面注入（把包喂进会话）属 S2，不在本面。

## Further Notes

### Premortem（三大死因 + 护栏）

- **`~/.claude.json` 被 Claude Code 写脏或格式漂移** → 护栏：文件级解析失败 = 空集 + 不炸 server；条目级 zod 校验失败 = 跳过该条；daemon 侧同律。UI 空态文案同时承担「文件坏了」的引导。
- **server 展示与 daemon 执行读的不是同一份文件**（多机部署）→ 护栏：Q6 决策即「各读各机」，文档与空态文案注明；daemon 每回合 canon 日志行打出实际加载的 slug 集，跑偏一眼可见。
- **drop 两表丢用户已登记数据** → 护栏：migration 内先导出 `~/.pacman/legacy-export-<ts>.json` 再 drop；release note 注明重新勾选路径（来源已换本地，重新勾选秒级完成）。
