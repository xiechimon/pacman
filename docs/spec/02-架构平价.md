## 1. 进程模型与部署拓扑（A1）

### 1.1 三段组成

```
浏览器 (React SPA, 同源)  ──HTTP + SSE──┐
                                        ├─ pacman-server（编排 API + DB + git 托管 + cron + 通知）
executor daemon (独立进程) ──HTTP + SSE─┘   ↑ 经 serverUrl 连接（本机或异机，LAN/云皆可）
```

- **锁定**：三段形状与 todos.dev 同构（r3 §1/§8 实测其即此形状）；默认部署文档按"本机一把跑齐"教（server + daemon 同机），但**协议面不折叠**——daemon 永远经 HTTP URL 连 server，"机器"可注册局域网/云服务器上另一台，兑现 BYOC 形状与免费 BYOC 档的功能平价。
- **沿用 D1/D3**：编排 durable 语义（step 队列、会话持久化索引、重试记录）全部 server 自持；pi 引擎只活在 daemon 进程内（r3 §1.5 executor=pi 构建的同构事实）。
- **沿用 D5**：web 前端 = 普通 SPA，不假设与 server 同进程；macOS 桌面壳（Electron/Tauri 类）与 PWA 包同一前端，架构不需改动（#34 Notes 桌面兼容前提兑现）。

### 1.2 实时通道（**锁定**，r3 §8.1 实测"全 SSE 无 WebSocket"）

| 通道 | 端点 | 事件（观测） |
|---|---|---|
| 团队流（浏览器） | `GET /api/teams/{id}/stream` | `{"type":"ping","seq":n}` ~15s 心跳；`{"type":"machine_presence","machineId","online"}` |
| 会话流（浏览器） | `GET /api/conversations/{id}/stream` | transcript 实时流（r3 §3.5 抓包） |
| 机器 wake（daemon） | `GET /api/machine/stream` | 低延迟派发唤醒（r3 §1.5） |

看板非 presence 类更新：**[推断]** 走查询失效重取（React Query 类轮询，r3 §8.1 观测窗口未见任务事件入 team stream，原话"疑走轮询/失效重取"）。复刻采同策略：SSE 仅作提示信号，数据一致性靠重取。

### 1.3 数据所有权边界

| 持有方 | 数据 |
|---|---|
| server（DB） | todo/build/phase 历史、plan 卡、transcript 消息与工具行（经上传回传）、team 资源（agent/skill/mcpServer/provider/secret/apiKey/machine 记录/schedule/notification）、tokenUsage 记账 |
| daemon（本机） | worktree checkout、pi `chat-sessions/`、`machine.json`/`device.json`/`daemon.json`/`daemon.log`、`outbox/`（出站事件缓冲，离线补发 **[推断]**，r3 §1.3） |

transcript 上行 = `upload-urls/<stepId>` 预签名上传（r3 §1.6，观测存在）。存储引擎/模式细案 **移交 #43**（00 已定此边界）。

## 2. 租户与简化边界（A2/A3）

1. **用户**：seed 单本地用户；启动即自动登录，`GET /api/auth/session`、`/api/user/me` 端点保形返回该用户。无注册、无邀请、无登录页复刻（#35 只盘公开页；登录后 workspace 才是平价对象）。
2. **团队**：`team` 表与全部 `teamId` 路径段形状保留，数据恒 seed 一行。多租户 SaaS 运维本就 Out of scope（地图）。
3. **成员**：团队页真人成员区只渲染自己一行 + Agent 计数（r3 §4 观察"成员计数把 Agent 计入"）。invite/join 流不实现。
4. **付费触点（锁定，Q15 裁决）**：r2 §7 全部 Pro 墙与升级弹窗**不复刻**——机器位数不限（r2 §7.1 `1/4` 门、r3 §1.2 限额弹窗均为对照物非复刻目标）、providers"新建"按钮恒在（r3 §2 门控观察为 todos.dev 行为，不采）、托管 repo 无墙、无 `升级到 Pro` 按钮。`plan` 字段保留于 team 记录形状但不参与任何门控。"槽位"概念（r1 §9.6 chief 对话不占槽的口径冲突）随付费面一并落空，不裁。
5. `maxConcurrent 3`（r3 §1.5 机器日志、§4 机器页文案"并发上限 3"）**不是**付费件：保留为 daemon 配置默认值。

## 3. repo 托管双形态（A4）

| 形态 | 落地 | 平价出处 |
|---|---|---|
| 托管 repo | server 按团队/项目 init **本地 bare repo**；对 executor 呈现 `http-backend` 远端 URL，形状对应 r3 §1.4 `https://git.todos.dev/<teamId>/<repoName>`（域名段进命名常量表 → #44） | r3 §1.4 全链实测（clone/push/merge/main 读回 83 号验证） |
| GitHub 接入 | 连号授权 → 用户自有 repo：executor push `conv-*` 分支、建 PR、读 PR/issues/CI workflow runs；看板"分支与 PR"区出现 PR 卡 | r3 §3.9 [推断: PR 语义仅 GitHub-backed 项目]；r1 docs 六能力组（Read the repo）；r2 §7 GitHub 路径 free 可用 |

- **锁定**：git 服务端组件用 git 自带 `git http-backend`（CGI），不引第三方 git host。凭证纪律同 r3 §1.4：托管 repo 的 git 凭证**仅 per-step 注入**（r3 实测手动 fetch 无凭证失败），daemon 不落常驻。
- 文件浏览面（`/api/projects/{id}/tree?ref=`、`/file?path=&ref=`，r3 §8.2 实测）服务项目页 `Tasks | Files` 分段开关（r1 §461 changelog）：读裸库 ref 树与单文件，server 端实现，无检出要求。
- 项目创建流两分支（导入 GitHub / 托管新建）UI 按 r2 §9 D 组截图为靶。

## 4. 编排状态机与时序（A5–A8）

### 4.1 phase 九值权威（A5，**锁定**）

一 todo 恒恰处一个 phase（`[docs_concepts]`、`[docs_todos]` 两表一致，r1 §7.4）。内部名取 docs 序：

| 内部值 | 语义（docs 原文） | 看板列（6 列，r2 §4.1） | 证据 |
|---|---|---|---|
| `todo` | 已建档未开始 | 待开始 | API 实测（r3 §3.0） |
| `queued` | 已启动，等空闲机器 | 待开始（折叠） | docs 表；折叠映射 **[推断]**（r1 §7.4 本票推得） |
| `planning` | 读仓库写计划 | 规划中 | docs 表（r3 "planning 未采到 [推断同族]"由此补实） |
| `confirm` | 计划就绪等你 | 待确认 | docs 表 + UI"确认方案"按钮实测（r3 §3.4） |
| `building` | 在改 | 执行中 | docs 表；r3 `exec` 猜测作废，正名 `building` |
| `review` | 改动就绪等你 | 待验收 | API 实测；`待验收≡审核` 同 phase（CONTEXT.md 裁决沿用） |
| `done` | 已接受，若选了则已合并 | 已完成（近 7 天） | API 实测 + changelog "Done (last 7 days)" |
| `failed` | run 停在错误上 | 钉执行中列顶 | docs 表 + changelog 原文（r1 §7.4） |
| `closed` | 未完成即搁置 | 不占列 **[推断]**（6 列无 closed 列；右键 Close 菜单项实测 r1 §443） |

字段其余形状照抄 r3 §3.0（`phaseAt/seqNum/orderIndex/tagIds/spec/assignment/agent/latestBuildId/lastRunAt/hasChanges/hasPlan/buildHistory/sourceTodo/v`）。

### 4.2 build 与 step 模型（A6，**锁定**：r3 §1.5/§3 实测语义 1:1 收录）

- **实体等式**：一次运行 = 一个 build = 一个 conversation = 一个 worktree + 一条 `conv-<conversationId>` 分支；`buildId ≡ conversationId`（r3 §3.0 实测）。Conversation/Plan/Transcript 为 facet 非实体（CONTEXT.md 沿用）。
- **step 队列 server 持有，机器 claim**：三类步 = 规划步、执行步、合并步（r3 §1.5 观测）；机器页文案 canon：「领取构建、规划与审核任务并运行 Agent。并发上限 3」（r3 §4）。
- **主时序**（全链 r3 §3 实测）：

```
创建 todo(POST /api/projects/{id}/todos {title,spec}) → phase=todo
点「开始」→ 开始任务 dialog（Agent 可空 / 「规划与执行分用不同 Agent」开关 / 先做规划 | 立即执行）
→ POST /api/projects/{id}/builds → server 入队规划步
→ 机器 tasks/claim → workspace 准备(准备工作区...) → 规划步(new session) → plan 卡(v1) → push 分支
→ phase=confirm →（人工）确认方案 → 执行步 → transcript 流(text_delta/toolcall/edit/bash 行) → push
→ phase=review →（人工）完成 → 确认弹层「将改动合并到默认分支」→ POST /api/builds/{id}/merge
→ 202 {delegated:true} → 机器领合并步(continue session 复用执行轮会话) → git merge --no-edit → 时间线「发起了合并」+ 结果行 + 🎉 → phase=done
```

- **确认回路**：驳回入口 = 面板底部 `请求修改…` textarea → 新方案版本（**[推断]** v2 机制，r3 未实走）。
- **失败与重跑**（r3 §3.7 实测）：机器离线 → `failed` + canon 文案「运行该任务的机器已离线 / 请将其重新上线，或重新运行任务以改派其他机器。」+ 按钮 `重新运行`（新 conv/新分支/新 build，重开开始 dialog）与 `复用方案→直接执行`（跳过规划，时间线首行「复用了上一次运行的方案。」）。**步级失败无自动重跑**；自动重试仅 pi provider 流级（`auto_retry_start/end` 事件，r3 §1.5，pi 自带）。幂等停止（重跑时 agent 判定内容已在 main → 停 `review` 不重复改）为涌现行为，不硬编码。
- **恢复到此处**：每步行 hover 按钮（r3 §3.5 实测 UI），后端 = worktree checkpoint `git reset --hard + clean -fd`（r3 §1.4），语义细节 **[推断]**（未实走回退）。

### 4.3 Chief（总管）结构契约（A7，**锁定**结构层）

- **身份**：每 用户×团队 一个（CONTEXT.md 沿用）；领域上是特例 Agent 实例（配置面同 Agent：provider/model/思考强度），**不是**普通 worker Agent 子类型混称。端点 `chief`、`chief/threads` 形状保留（r3 §8.2 实测存在）。
- **界面**：悬浮球 + `C` 快捷键 → 居中圆角弹窗（~640px，r2 §8.6 全录）：主题芯片、`新主题/总管设置/全屏/关闭`、门控条文案 canon、空态 Hero「你想做点什么？」+ 2×2 示例卡、底部 `有什么可以帮你的？`。`总管设置` 行为未观测（r2 §9）——**[推断]** 为 model/凭据选择器，实验票复核。
- **接口契约**（本册钉的边界，实现按此写）：
  - 输入：用户自然语言消息 + 团队资源清单（projects/agents/skills/machines/providers）。
  - 输出（均实测语义）：建 todo（「任务将自动创建并进入『待开始』列」r3 §3.11 P1）；分派/启动（开始 dialog 指派）；写 schedule（「也可以直接告诉总管某个任务要多久重跑一次，它会替你写好规则」r3 §9）；对话式读（progress/看板/分支）。
  - 线程：多主题对话（`chief/threads`），模型位可显 `n/a`（r2 §8.6 实测态）。
- **策略层 [推断]**：怎么拆任务、怎么挑 Agent、prompt 长什么样——todos.dev 全黑盒（r3 §11）。复刻采"能产出上述输出的最小 agent loop"（Chief = 一个挂团队工具的 pi 会话），行为分毫不求同。**实测校准归实验票**「实验：Chief 黑盒行为观察」（#46），产 r5 后回填本节，改判触发见 §11。

### 4.4 memory 最小机制（A8，**锁定**为最小形，全 [推断]）

- 实体：`agent.memory` 条目集合；Agent 详情三 tab（概览/记忆/权限，r3 §4 实测）；空态文案 canon「尚无记忆。Agent 会在工作中将值得沉淀的经验存入此处。」；列表/删除 API 保形。
- 读路径：每步开跑时，宿主把该 Agent 记忆条目注入 systemPrompt（经 D3 `before_agent_start` 缝）。
- 写路径：宿主提供的 agent 工具（内部名 `remember`，品牌位→#46 校准后定稿 r3 观测零写入实例）。
- todos.dev 真实沉淀策略未观测（r3 §11"未观测到实例"）——本机制只求界面与概念平价可运转，实验票若证其行为不同（如按任务结束自动蒸馏），按 §11 改判。

## 5. executor 协议（A9·机器面，**锁定**：r3 §1 全量 1:1）

### 5.1 CLI 形态

- 独立发布物（npm 全局装，含平台二进制，r3 §1.1 包体形状）；命令面 `start / stop / restart / logs [-f] / logout / status / version / provider`；`provider` 仅提示「Providers are managed on the website」（r3 实测语义：凭据管理在 web，CLI 不代做）。
- env：`SERVER_URL / API_KEY / TEAM / WORKSPACES_DIR / HOME`（原名 `TDS_*`，前缀进命名常量表 §5.8）。
- `start` 选项照抄：`--foreground`（attached 供 pm2/systemd/容器）、`--api-key <k> --team <id>`（非交互注册，覆盖既有注册以换团队）、`--name`（默认 hostname）、`--server`、`--workspaces-dir`（持久；**父目录必须已存在**护栏 canon：「if that drive is unmounted … refuses to start instead of cloning onto the boot disk」）。
- 默认 detached + supervisor 跨崩溃保活；机器 shell 权限改动秒级热加载（「no restart needed」r3 §1.1 help 原文）。

### 5.2 注册两条路径（r3 §1.2 实测）

1. 浏览器授权：`start` 无参 → 开登录页授权团队（`enroll/start` + `enroll/poll`）。
2. key 非交互（云服务器文案路径）：`--api-key --team`；「添加机器」弹窗底部展开命令 + 「获取 API key →」跳 api-keys 页（r2 11b 文案）。
- `logout` 只 Forget 本机；服务端机器记录保留，重注册**复用同一 machineId**（r3 实测 + [推断] 按 key/team 认机器）。

### 5.3 本地状态布局（r3 §1.3 实测，目录名品牌位 → #44）

`machine.json{machineId,token(64hex),teamId,serverUrl}` / `device.json{deviceId(32hex)}` / `daemon.json{pid,startedAt,runner}` / `daemon.log`（supervisor/machine/step/workspace/recover/wake 前缀）/ `outbox/` / `chat-sessions/` / `agent-runtime/` / `workspaces/`。

### 5.4 领取、心跳与恢复（r3 §1.5/§1.6 实测）

- 长轮询 `tasks/claim`（节奏 ~75–76s）+ `stream`（wake SSE）双通道；断网 claim 指数退避封顶 30s，presence 心跳并行失败，进程不退出。
- 上线序列 canon：`Loading pi runtime…` → `Online (machineId=…); polling <url>` → 闲置防睡（caffeinate 类）→ `[recover]` 步 journal 恢复（细节 **[推断]**，r3 未见 pending 样本）→ `maxConcurrent changed -> 3` → `[wake] push channel connected`。
- 步骤 journal：`heartbeat/<stepId>` 续活；`tool/<stepId>` 工具调用回传；`done/<stepId>` 收尾；`upload-urls/<stepId>` 预签名产物上传；`token/<stepId>` per-step 凭证下发（不落盘常驻，**[推断]**——据端点名 + git fetch 无凭证失败，r3 §1.6）。

### 5.5 worktree 契约（r3 §1.4 实测全套照抄）

| 项 | 契约 |
|---|---|
| 基座 | `<workspacesRoot>/<projectId>/repo`（baseRepoDir） |
| 任务目录 | `<workspacesRoot>/<conversationId>`（目录名=UUIDv7） |
| 分支 | `conv-<conversationId>`（前缀 `tds/` 为品牌位 → #44）；`worktree add -b`，base=`origin/<convBranch>` 否则 `origin/<defaultBranch>` |
| 复用/恢复 | 存在→reused；checkpoint→`reset --hard`+`clean -fd`（restored）；陈旧→`remove --force`+`prune`+`branch -D`；孤儿回收 TTL **7×24h** |
| 并发保护 | `projectLock(projectId)` 串行化同项目工作区操作 |
| 防分叉护栏 | `remote branch diverged`：`origin/<branch>` 有本机没有的提交且 worktree 不在该分支 → 抛错 |
| push | 每步结束自动 push 本 conversation 工作分支；合并用 `git merge --no-edit <ref>` |
| 重试预算 | push 覆盖 git-host 5xx 窗口；冷 worktree ls-remote+fetch「~2 min typical, ~8 min worst on /done's path」；merge 轮走 gitNetwork（r3 原文数值） |
| 强制同步 | 「丢弃代码修改并删除非忽略的未跟踪文件；保留忽略内容。仅本次生效。」（r3 §3.9 面板文案 canon） |

### 5.6 事件与工具面（r3 §1.5）

- pi 流事件词表：`text_delta` / `thinking` / `thinking_delta` / `toolcall_end` / `message_update` / `message_end` / `message_stop` / `compaction` / `compaction_start` / `compaction_end` / `auto_retry_start` / `auto_retry_end` / `steer` / `done` / `error` / `wake` / `shutdown`；配置 kind：`api_key` / `oauth` / `http` / `stdio`。
- 流超时护栏：`streamFirstEvent 300000 / streamIdle 480000 / streamBodyTimeout 540000` ms（r3 bundle 原文）。
- 机器侧自定义工具三件（描述 canon 照 r3）：`web_fetch`（URL 文本 ≤8000 字符）、`remote_shell`（团队内已授权他机持久 shell，对应 Agent 权限开关「远程 shell」）、`push_branch`；其余工具面 = pi-coding-agent 内建（bash/edit/read…，transcript 实测 `edit`/`bash` 行）。**隐私语义注意**：transcript 直露 worktree 绝对路径（r3 §3.5），复刻同款（平价）不做脱敏。
- 代理探测：启动读系统/环境代理并打印；代理死持续重试不退出（r3 实测 10+ 分钟）。

### 5.7 步骤生命周期（r3 §1.5 实测行序）
