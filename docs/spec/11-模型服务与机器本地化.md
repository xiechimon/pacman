# 11 · 模型服务与机器本地化

> 范围：`/app/resources/providers` 与 `/app/resources/machines` 两页本地化重写。覆盖 r3 复刻残留的两条 facade（providers 的「Pacman（内置）」行、machines 的「Pacman 托管机器」行——均为前端渲染的固定装饰，非库内数据），页面语义翻转为：pacman 不提供远程模型/机器服务，但可连接外界远端 provider 与本网机器。
>
> 上游参照 = todos.dev 现行形态（2026-09-28 登录态实测）：providers 页为 runtime tablist（pi / Claude Code / Codex），tab 内 = header 卡（runtime 说明 + 已安装在 <hostname>）+ 模型行（槽位 → 实际模型 id）；machines 页 = 托管行 + 本机行（带 per-runtime 开关真控件）+ 添加机器。本 spec 取其结构、弃其托管语义。

## Problem Statement

1. **providers 页语义错位**：页面把 38 项远端 provider preset 目录当内置 picker 投喂（`providerPresets()` + `PROVIDER_PRESET_IDS`），并在列表顶部渲染「Pacman（内置）」facade 行。pacman 是 local-first，自身不提供任何远程模型服务——页面承诺了不存在的产品面。
2. **machines 页语义错位**：同理渲染「Pacman 托管机器」facade 行（未启用）。托管形态在本架构不存在；用户真正拥有的是本机 + 自行接入的 LAN/VPS 机器。
3. **行可点感误导**：两页资源行渲染 `RowChevron` / `EllipsisVertical` / `StatusPill` 装饰，但 `<div class="res-grow">` 行无 click handler（#222/#231 出账注记：无后端面不渲染死钮）。实测（verify 栈逐钮探针）：两页真按钮（`.res-new` / `.res-add`）均可点、无 overlay 遮挡——用户复报的「按钮不可点」实为装饰误导。
4. **配置来源未自动化**：上游 Claude Code tab 直接展示本机 `~/.claude/settings.json` 的模型槽映射；pacman 侧模型清单目前只来自用户手工录入的 custom provider，无本地自动发现。

## Solution

| ID | 决策 | 落地形态 |
|---|---|---|
| **A1** | providers 页改 runtime tab 形 | tablist = `pi` / `Claude Code` 两个 tab（无「内置」字样；Codex 后续票再扩）。页面不再渲染「Pacman（内置）」facade 行 |
| **A2** | tab 内容契约 | 每 tab = header 卡（runtime 名 + 一行说明 + 「已安装在 \<hostname\>」）+ 模型行列表（显示名 → 模型 id）。行无 handler 时不渲染 chevron/三点（吸收行可点感收编，见 A7） |
| **A3** | pi tab 数据源 = custom providers | pi 是 pacman 自身运行时（daemon 路由的本地模型来源面）；其可用模型 = 用户经「添加服务商」配置的 custom provider 的 `models[]`。无 custom provider 时空态引导去 picker。pi 探测/未安装态归实现票钉死 |
| **A4** | Claude Code tab 数据源 = 本地配置直读 | server 端 `fs` 读 `~/.claude/settings.json`（`model` 字段 + `env.ANTHROPIC_*_MODEL` 槽位覆盖），不经 daemon、不经 web 直读 fs。文件缺失/解析失败 → header 卡转「未安装」态（给安装指引文案），不空报不崩 |
| **A5** | 38 项 preset 数据层全留、页面层让位 | `PROVIDER_PRESET_IDS` / `PROVIDER_OAUTH_PRESET_IDS` / `PROVIDER_XAI_PRESET` / `providerPresets()` / OAuth 授权链（#231/#243 着陆面）全部保留。「新建」钮改开 picker dialog（A6），preset 仅在 dialog 内出现 |
| **A6** | 添加服务商 picker dialog | 重构 `create-provider-dialog.tsx` 为上游形态：搜索框 + 38 项 preset 行（OAuth 族带徽标）+ 底部「自定义端点」入口（展开现有自定义网关表单）。点 preset 行 → OAuth 族走既有 authorize 重定向，api_key 族进该 preset 的密钥表单 |
| **A7** | 行可点感收编 | 资源行仅在挂载真实 handler（导航/菜单）时渲染 `RowChevron` / `EllipsisVertical`；纯展示行不渲染可点感装饰。本规约随两页重写落地，不单独建补丁票 |
| **A8** | machines 页 = 本机基线 + 已注册机器 | 删「Pacman 托管机器」facade 行。本机行始终在列表首、不可删：server 启动 seed（或 daemon 自 loopback enroll 时落 `kind='local'`）。每行带 per-runtime 开关（pi / Claude Code）真控件。添加机器流程不变（CLI 命令 dialog：`pacman start` / `--api-key` / 浏览器授权三路径已在位），LAN/VPS = 在目标机器上跑同一 CLI |
| **A9** | machine schema 增两列 | `kind: 'local' \| 'remote'`（默认 `'remote'`，loopback enroll 落 `'local'`）+ `enabledRuntimes: string[]`（JSON，默认 `[]` = 全关，UI 开关写这里）。drizzle migration 序号按合并时点 main 尾部 +1（票内不占号） |
| **A10** | chief-model-select 数据源切换 | 选项清单 = A3/A4 两 runtime 的模型并集 + custom providers `models[]`（现状逻辑保留）。preset 裸串兜底逻辑退役——页面不再投喂 38 项后，未命中选项的回显仍走裸串（#180 裁决不变） |
| **A11** | i18n 随票同步 | 新中文文案同 PR 同步 `apps/web/src/i18n/en.ts`（i18n-coverage 闸），不单独开票 |
| **A12** | verify feature map 先行 | T0 票先扩 `.claude/skills/verify-pacman/features/`（providers tabs / machines 本机行 / picker dialog 三面），实现票消费之；web spec + integration locator + 视觉几何断言随实现票同步（钉扎四面） |

## User Stories

1. 作为用户，我打开模型服务页看到 `pi` 和 `Claude Code` 两个 tab，每个 tab 头部写着它运行在哪台机器上，这样我知道模型来自本机配置而不是某个远端托管服务。
2. 作为用户，我在 Claude Code tab 看到与我本机 `~/.claude/settings.json` 一致的模型槽映射（default → …、opus → …），无需手工录入。
3. 作为用户，我点「新建」看到一个可搜索的服务商清单（含 OAuth 徽标）和底部自定义端点入口，可以把外界远端 provider 接进 pi 运行时。
4. 作为用户，我打开机器页看到本机在列表首且带 runtime 开关，我可以决定本机跑 pi 还是 Claude Code 任务；添加局域网机器或 VPS 时，dialog 给我可复制的 CLI 命令。
5. 作为用户，我不会再对着一个三点图标或 `>` 箭头点了没反应——没有动作的行不长可点感装饰。
6. 作为审阅者，我看总管压缩模型选择器的选项来自 runtime 模型清单与 custom providers 真值，页面隐藏 38 项 preset 后 chief 回显不空不崩。
7. 作为回归测试者，我看 verify-pacman feature map 先于实现扩好，实现票的 web spec / integration locator / 视觉几何同步翻红转绿，证据进 review。

## Implementation Decisions

### 模块改动清单

**shared**
- `packages/shared/src/records/machine.ts`
  - `machineRecordSchema` 增 `kind: z.enum(['local','remote'])`、`enabledRuntimes: z.array(z.string())`
- `packages/shared/src/records/provider.ts`
  - 不动（38 项常量全留，A5）
- 新增 `packages/shared/src/records/model-source.ts`（命名票内可再议）
  - runtime tab 封套 schema：`{ runtime: 'pi' | 'claude-code', installed: boolean, hostname: string, models: { id, name, slot? }[] }`

**server**
- `apps/server/src/db/schema.ts`
  - `machine` 表增 `kind`（text，默认 `'remote'`）+ `enabledRuntimes`（JSON text，默认 `[]`）
- `apps/server/src/services/machines.ts`（或新模块）
  - server 启动 seed 本机行：`os.hostname()` 匹配已有行则补 `kind='local'`，无则建行（idempotent）；daemon loopback enroll 同律
  - `PATCH /api/machines/{id}`（或既有机器路由族内增端点）：写 `enabledRuntimes`，body schema 落 shared
- `apps/server/src/services/providers.ts`
  - `getProvidersEnvelope` 不动；新增 `getModelSources(deps, teamId)`：pi 段 = custom providers `models[]` 投影；claude-code 段 = 读 `~/.claude/settings.json`（`os.homedir()` 解析，`model` + `env.ANTHROPIC_*_MODEL` 槽位），失败 = `installed: false`
- `apps/server/src/routes.ts`
  - 新增 `GET /api/teams/:id/model-sources`（providers 路由旁，1334 行族）

**web**
- `apps/web/src/resources/providers-page.tsx` + `resources.css`（或新 `providers.css`）
  - 整页重写为 tablist 形：tab 状态进 search param（`?runtime=pi|claude-code`，刷新/分享可回定位）
  - header 卡组件 + 模型行组件；无 handler 行不渲染 `RowChevron`/`EllipsisVertical`（A7）
  - 空态：pi tab 无 custom provider 时引导开 picker
- `apps/web/src/resources/create-provider-dialog.tsx`
  - 重构为 picker：搜索框（客户端过滤 38 项）+ preset 行（名称表见上文；OAuth 族徽标）+ 底部「自定义端点」disclosure 展开现有表单
  - OAuth 分支逻辑（`onConnect` / `#231` 错误行 / `#243` reason 三译）原样保留
- `apps/web/src/resources/machines-page.tsx`
  - 删托管 facade 行；本机行（`kind='local'`）钉列表首 + 禁删；runtime 开关组件（`role="switch"`，PATCH 写 `enabledRuntimes`）
  - `CreateMachineDialog` 结构不动（CLI 命令即真相）
- `apps/web/src/chief/chief-model-select.tsx`
  - 选项数据源从 providers 封套投影 → `GET model-sources` 投影 + custom providers 并集（A10）
- `apps/web/src/api/hooks.ts` + `mappers.ts`
  - `useModelSources` 查询 + mapper；`useMachines` 增 PATCH mutation
- `apps/web/src/fixtures/`
  - fixture 面补 runtime tabs / 本机行 scenario 数据（fixture 律：无 live 时 canon 展示）

**i18n**
- `apps/web/src/i18n/en.ts`：随各实现票同步新增文案的英文条目（A11）

**verify / e2e**
- `.claude/skills/verify-pacman/features/`：T0 先扩三面（providers tabs、machines 本机行+开关、picker dialog）
- `apps/web` e2e spec + integration locator + 视觉几何断言：随 T3/T4 同步（钉扎四面，漏任一 CI 红本地无感）

### 数据契约

- `GET /api/teams/:id/model-sources` → `{ sources: [{ runtime, installed, hostname, models[] }] }`（schema 单源在 shared）
- `PATCH /api/machines/:id` body：`{ enabledRuntimes: string[] }`（元素词表 = `'pi' | 'claude-code'`，shared 常量）
- providers 既有封套 `{ presets, providers }` 不动；picker dialog 消费 `presets` 段
