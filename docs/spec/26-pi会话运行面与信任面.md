# 26 · pi 会话运行面与信任面（trust / telemetry / settings / cost / cache）

> 范围：daemon 的 pi 会话（`apps/daemon/src/backend/pi.ts`，in-process SDK）此前有三处「沉默的默认值」与一处「恒 0 的成本位」。本册把五项决定显式落码：project trust 判什么、telemetry/版本检查关到什么程度、file-backed settings 绕过哪些、成本从哪来到哪去、缓存保留档怎么设。
>
> 参照：issue #925、#927；pi 1.0.4 文档（`docs/security.md` §Understand project trust、`docs/settings.md`、`docs/models.md`、`docs/custom-provider.md`、`docs/environment-variables.md`）与 dist 源（文内逐处引用）。票面写作时 pi 为 0.86.0，升级已发生——本册全部事实按 **1.0.4** 重新核对。

## Problem Statement

1. **project trust 零处理，且方向与票面猜测相反。** pi CLI 非交互场景默认 `"ask"` → 跳过受保护资源；但 daemon 走 SDK + `SettingsManager.inMemory`，其 `projectTrusted` 缺省 **true**（`settings-manager.js:187/214`）。后果：任务 worktree 里的 `.pi/SYSTEM.md` / `.pi/APPEND_SYSTEM.md` 会**静默成为会话系统提示词**（`resource-loader.js:941-956` 按 `isProjectTrusted()` 放行 → `agent-session.js:1272` 消费 `loader.getSystemPrompt()`）。任务仓的内容由此可以改写 agent 的职责面——旁路 pacman 自有的全部授权缝（简报 = runner 写的 AGENTS.md、skills = catalog+allowlist+读闸（spec 14/#917）、MCP = server 授权桥、命令 = #866 闸）。`.pi/mcp.json` / `.pi/extensions` 今天不生效只是因为 SDK 面没有 builtin 扩展注入（`resource-loader.js:247` builtin 集来自 `extensionFactories`，daemon 不传）——是巧合不是决定。
2. **telemetry 默认开着。** pi `enableInstallTelemetry` 缺省 **true**（`settings-manager.js:777`），SDK 请求面会消费它：`sdk.js:194` 每次流请求经 `mergeProviderAttributionHeaders` 给 OpenRouter/NVIDIA/Cloudflare 宿主加 attribution 头（`provider-attribution.js:28`）。安装遥测与 pi.dev 版本检查本体是 CLI 入口路径（`interactive-mode.js:1010`、`package-manager-cli.js:577`），SDK 会话不触发，但子进程继承面无钉。
3. **file-backed settings 被整体绕过且无声明。** `SettingsManager.inMemory` 使 pi 的用户级/项目级 `settings.json`（retry、modelOverrides、httpProxy、cacheWarming、packages…）对 daemon 会话全部失效。绕过本身可以是正确取舍，但清单从未被声明过。
4. **cost 恒 0。** pi-ai 的 per-message `Usage.cost`（USD 五分项，`types.d.ts:291-311`，由 `models.js:657 calculateCost` 按模型价算出）在 daemon 的投影里被丢弃（`PiMessageLike.usage` 只有四维）；custom 端点物化进 `models.json` 的价格恒零（`CUSTOM_MODEL_DEFAULTS.cost`），全链无价格来源。
5. **缓存保留档未设。** `PI_CACHE_RETENTION`（pi-ai 五个适配器消费：anthropic-messages → `cache_control.ttl:"1h"`；openai-completions → `prompt_cache_retention:"24h"`；openai-responses/bedrock/pi-messages 同族）与缓存预热（`cache-warmer.js`，settings `cacheWarming` 缺省 `"streaming"` = 会自发发后台刷新请求）都吃 pi 的沉默默认。

## Solution

| ID | 决策 | 落地形态（单源） |
|---|---|---|
| **D1** | project trust = **deny**：任务 worktree 的 `.pi/` 受保护资源一律不加载 | `daemonSettingsManager()` = `SettingsManager.inMemory(PI_DAEMON_SETTINGS, { projectTrusted: false })`（backend/pi.ts；open() 与测试共用同一构造，声明与行为不可能分叉） |
| **D1a** | deny **留痕**，不静默 | `detectTrustProtectedResources(cwd)`（八件词表 = pi security.md，`TRUST_PROTECTED_ENTRIES`）非空 → `[trust] denied: <…> present in worktree …` canon 行（DAEMON_LOG_PREFIXES 第十族；空 worktree 静默） |
| **D2** | telemetry / 版本检查 = **off**，三层钉 | ① `PI_DAEMON_SETTINGS.enableInstallTelemetry: false`（翻掉 pi 缺省 true → attribution 头不发）；② env 钉 `PI_TELEMETRY=0`（`telemetry.js:6` env 优先于 settings，双保险 + 子进程继承面）；③ env 钉 `PI_SKIP_VERSION_CHECK=1`（`version-check.js:66`；`PI_OFFLINE=1` 既有钉已使 `getLatestPiRelease` 短路，`version-check.js:37`） |
| **D3** | file-backed settings = **显式声明绕过** | `PI_SETTINGS_BYPASS`（九族清单，每条带「绕过后由谁负责」）为配置面正本，本节为文档面；`PI_DAEMON_SETTINGS` = 会话全部 settings（compaction 开 / telemetry 关 / cacheWarming 关）；上线序列落 `[machine] pi policy: trust=deny telemetry=off version-check=off cache-retention=<档> settings=in-memory …` 宣告行——运行面从 daemon.log 可读，不靠翻代码反推 |
| **D4** | 成本 = **pi 报什么记什么**，宿主零计算 | per-message：`message_end` 行携 `usage`（含 cost）原样透传（messageRecordSchema loose 位，事件流追溯面），runner 对每条 assistant 消息落 `[step] message usage: <model> input=… output=… cacheRead=… cacheWrite=… cost=<total>` 行（daemon.log 运行时对账面——「落库成本 ← 哪次请求算出来的」逐条可查）；聚合：`mapPiSessionEvent` 按 `<provider>/<modelId>` 累积 `ModelUsage.cost`（可选位）→ `done` → machine wire（`modelUsageSchema`，旧 daemon 不带 = 缺省）→ server `token_usage` 五列（real，migration 0027）→ `GET /api/builds/:id/usage` |
| **D5** | 价格来源 = **管理员声明，pi 计算**（不自造价格表） | `providerModelSchema.cost`（可选，USD / 1M tokens，pi 目录价语义、ModelCostRates 同形）经 provider 配置 → `materializeProvider` 覆盖 `models.json` 条目的零默认 → pi `calculateCost` 据此算 per-message cost。未声明 = 零价 = cost 恒 0（如实反映「无价格来源」）；preset provider 用 pi 内建目录价。API 面可配，UI 表单不在本册 |
| **D6** | 缓存保留 = **显式档，缺省 short** | `PACMAN_PI_CACHE_RETENTION`（ENV_VARS.piCacheRetention）：`long` 才长保留，未设/乱值一律 `short`；`PI_CACHE_RETENTION` 恒被显式落值（short 也落——策略从进程环境可读）。缓存预热显式 **off**（`PI_DAEMON_SETTINGS.cacheWarming`）：无人值守会话不发任何背景 LLM 请求，花销只来自 agent 步本身；模型侧 `promptCache` 生命期**不声明**——其唯一消费面是预热资格（`cache-warmer.js:26-30`），预热既关，声明无意义 |

### 为什么 deny 而不是 approve

任务 worktree 是 agent 自己的工作区：其中的文件一部分来自模型之笔。approve 意味着「模型写下的 `.pi/SYSTEM.md` 可以改写下一步的系统提示词」——一条自我提权通道，且旁路 D1 列出的全部 pacman 授权缝。pacman 需要的项目级输入只有一条：runner 写入的简报上下文文件（AGENTS.md 族），而它**不受 project trust 门控**（pi security.md：context files load regardless of project trust；`noContextFiles` 未设）——deny 不伤简报通道，集成面有零回归断言。agentDir（`PACMAN_HOME/agent-runtime`）级的 `SYSTEM.md` 仍可加载：那是 daemon 自管目录，不是任务输入。

检测点 = 每步会话 `open()`（pi 会话按步建、按步弃）：步中途才出现的受保护资源在**下一步 open** 被点名；deny 决定本身不依赖检测——`projectTrusted:false` 是构造期恒量，检测只负责「deny 实际拦截到了什么」的留痕。

### 为什么 retention 缺省 short 而不是 long

long 会向网关发送新字段（`prompt_cache_retention` / `cache_control.ttl`）。部分网关通道确定性拒绝未知字段——#654 的 `store` / `max_completion_tokens` 同族教训，relay 侧不可修（公司网关）。short = pi 缺省档，请求面与既往逐字节同形，零暴露；long 是「知道自家网关认这个字段」的操作员的 opt-in。预热同律从紧：它的期望节省判定（≥$0.05，`cache-warmer.js:7`）依赖目录价，custom 端点无价 = 不触发，但 preset 模型会真发背景请求——显式 off 把「会不会花」从推断变成声明。

## 验收（seam，两票原文）与判据落点

| 票面 seam | 判据落点 |
|---|---|
| trust：worktree 放 `.pi/` 受保护资源，行为与明确决定一致，被拒时有可观测记录 | 集成 `integration/test/pi-session-policy.test.ts` 失败方式 1/2：local 仓种植 `.pi/SYSTEM.md` 劫持 marker → stub 请求面无 marker + `[trust] denied:` 行点名 + 简报文本仍在 |
| telemetry：无人值守会话不产生安装/使用遥测上报（可观测） | 单元 `apps/daemon/test/pi-session-policy.test.ts`：`PI_DAEMON_SETTINGS.enableInstallTelemetry=false` 且 `daemonSettingsManager().getSettings()` 行为相符；`piUnattendedEnvPins` 钉 `PI_TELEMETRY=0`/`PI_SKIP_VERSION_CHECK=1`（已有显式 env 不抢）；集成失败方式 3：策略宣告行落 daemon.log |
| settings 绕过：策略是声明出来的（配置/文档可见清单），行为相符 | `PI_SETTINGS_BYPASS`（配置面正本）+ 本册 D3（文档面）+ 单元断言清单盖住票面四族（defaultProjectTrust/retry/modelOverrides/httpProxy）且每条有 policy 说明 |
| 成本：真实 step 结束后落库/事件流可见该步成本，可追溯 per-message usage | 集成失败方式 5：声明价 provider 跑真 plan 步 → `GET /api/builds/:id/usage` 与 DB 行 cost 五分项 = worked example（2 消息 × pi calculateCost 逐条值）；追溯面 = `message_end` 行携 usage（单元 `map-pi-event.test.ts` #927 两例）+ daemon.log `[step] message usage:` 行逐条对账（单元 `runner-error-lifecycle.test.ts` 两例 + 集成/live probe 行数与数值钉） |
| 缓存：保留策略显式设置（配置可读），长会话命中率与设置相符 | 单元：`resolvePiCacheRetention` 值域 + `piUnattendedEnvPins` 恒显式落 `PI_CACHE_RETENTION`；集成失败方式 4：`PACMAN_PI_CACHE_RETENTION=long` → stub 收到的请求体带 `prompt_cache_retention:"24h"`（宿主侧因果链到头——命中率本身是 provider 侧行为） |
| 回归：既有四维统计与 web 侧命中率零变化 | web 零文件改动；四维断言原值（集成失败方式 6：output=1960/cacheRead=200/input=0/cacheWrite=0 与 stub 报告逐值一致）；`map-pi-event` 无 cost 消息 → 不产 cost 键；shared 快照 7 块全为增量 |

## 兼容面

- **mixed-version**：旧 daemon → 新 server：`modelUsage.cost` 缺省，upsert 按 0 记；新 daemon → 旧 server：zod object 默认 strip 未知键，cost 位被忽略，四维照旧。
- **claude-code 后端**：usage 映射不产 cost（其 SDK 面无同形位），`ModelUsage.cost` 可选位保持缺席——四维口径两后端一致，成本维是 pi 后端能力位。
- **chief 记账**（`services/chief.ts` 四维聚合）不动：成本维的 chief 面读口径不在本册。
