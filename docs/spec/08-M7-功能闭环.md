## 0. 决议一览

| # | 项 | 定案 |

| C2 | 范围 | 当前已渲染的交互元素 + 反向差距（todos.dev 有而 pacman UI 没有的面）；继承 02 册排除项 |

## 1. Problem Statement

真实使用中大量按钮点击无反应：composer 流式传输时停止钮无 handler、project 页空态新建钮无 handler、详情/资源/设置各面散布菜单桩与死钮。这些按钮在原版 todos.dev 中多为真功能（r8 §3.1 实测 AI 审核为完整 agent 回路），pacman 复刻了像素未接功能。06 册转自主产品后，功能闭环的取舍标准从「todos.dev 等价」转为「自有产品判断」，但「已渲染的交互必须生效」这一底线不变。

## 2. Solution

一次里程碑式收编：先合并四方来源出一本**差距台账**（唯一正账），再按依赖层分五波清零。处置范式沿用 #149/#163/#222 已立二分律——**有对象面 → 接真；无对象面 → wontfix 出账 + 移除渲染 + e2e 断言钉死**。每个功能面闭环必附 verify-pacman 真栈证据。

## 3. User Stories

核心路径：

1. As a 用户，I want 流式传输中点击停止钮能中断当前 build，so that 失控的 agent 步不必等超时
2. As a 用户，I want project 页空态的「新建任务」钮能开新建对话框，so that 空项目里能建第一个任务
3. As a 用户，I want 新建项目时「选择仓库」钮能列出可选 repo，so that 项目能绑定代码仓库
4. As a 用户，I want 看板/详情/资源各页的「更多」菜单钮都能开出真菜单，so that 次要操作可达
5. As a 用户，I want 详情页 transcript 的折叠钮能收起长消息，so that 长 build 记录可浏览

重功能（M7-W5，一功能一票）：

6. As a 用户，I want 待确认关口发起 AI 审核（选 Agent → 审核步 → blocking 自动修订），so that 方案质量有第二双眼睛（r8 §3.1 规格在册）
7. As a 用户，I want composer 与新建任务能添加附件，so that agent 能看到截图与文件（规格 M7-W1 补采）
8. As a 用户，I want composer 与新建任务能 @提及 todo/agent，so that 上下文引用显式化（规格 M7-W1 补采）
9. As a 用户，I want 新建任务对话框能添加标签，so that 任务分类在创建时完成
10. As a 用户，I want 分支对话框的「同步到机器」可选机器并执行同步，so that worktree 状态可控

反向差距（台账校准后转票）：

11. As a 用户，I want todos.dev 有而 pacman 缺失的功能面被盘点登记，so that 闭环边界是全书而非抽样

## 4. Implementation Decisions

### 4.1 波次结构

- **M7-W1 总账 + 补采**（单票，后续所有票的 blocking 前置）：
  1. 四方对账出差距台账（r1/r2 功能清单 × 当前 UI 交互面 × 05 册 §6 登记面 × 2026-09-26 扫描初值）；
  2. todos.dev 补采附件/提及两处交互规格（账号可用；r8 §3.1 先例的实测格式）；
  3. 后端能力盘点：server routes × daemon 能力 × 前端需求三方对账，W3/W4 的洞在此浮出，不留到施工期；
  4. 产出 = 本册附录 A 升格为正账 + 每行处置分支（接真 / wontfix 移除）+ 各票输入。
- **M7-W2 纯前端**：档 3 菜单桩 + 档 4 外链处置 + 档 1 纯前端部分（空态新建接 onNewTask、选择仓库接 repo 列表）。无 server/daemon 依赖，票间无 blocking 边，可并行。
- **M7-W3 server**：停止（steer 端点）、附件上传/存储、提及解析、标签写路径等端点补全。
- **M7-W4 daemon**：steer 中断（收编 06 册 D9 W3）、附件同步、AI 审核执行能力。
- **M7-W5 重功能**：AI 审核 / 附件 / 提及，一功能一票，开工前重新切片评估。

### 4.2 处置二分律（沿用 #149/#163/#222 先例）

每行台账只有两种终态：
- **接真**：对象面存在（local-first 可承载）→ handler 接真链路；
- **wontfix 出账**：无 local-first 对象面 → 移除渲染 + 实现位注记 + `dead-buttons.spec.ts` 断言钉死。

### 4.3 语音

composer 与新建任务对话框的语音按钮移除（C5）。例外的例外：若 M7-W1 补采发现提及/附件交互与语音按钮强耦合（同一 toolbar 布局假设），由 W2 票内顺带调整，不单独立项。

### 4.4 缝

不新建缝。最高缝 = verify-pacman（隔离栈真用户路径）；其下沿用 integration（stub-llm 链路，server×daemon 协议）、apps/web e2e（fixture 行为断言）、vitest。parity harness 身份承 06 册 D1 = 回归工具，M7 不消费其「平价门禁」语义。

## 5. Testing Decisions

- 好测试 = 只测外部行为（按钮点击后的真实效果：API 调用、状态迁移、UI 反馈），不测实现细节。
- **每功能 verify-pacman 证据**（C6）：截图 + API JSON + SQLite 行落 `.claude/verify-evidence/`。
- wontfix 移除类处置沿用 `apps/web/e2e/dead-buttons.spec.ts` 钉断言（先例 #149/#222）。
- server/daemon 协议层走 integration stub-llm 链路（m4b 先例）。
- feature map 按需维护（C6）：功能面变化的票跑 maintain-verification-skill，纯接线票不跑。
- 测试规则承 AGENTS.md：禁补单测、E2E 为主、先列失败方式再写实现。

## 6. Out of Scope

- 语音输入（功能不做，按钮移除——C5）。
- 02 册排除项：付费墙/多租户/注册邀请/invite 流/云端多租隔离。
- streamdown（07 册：暂缓 + 触发线）；preview-token（05 册 §6：触发条件未至）。
- todos.dev 基线重拍与像素对拍（06 册 D1 已解除对拍义务）。
- 本轮台账之外的新功能创意（涌现制归 06 册 D9 W4+）。

## 7. Premortem 护栏（假设 M7 失败的三死因）

1. **总账漏项**：r 文档实测覆盖不全，施工后期又冒新洞 → 护栏：M7-W1 验收 = 四方对账 + 补采顺带全站扫描 + 后端能力盘点三合一时才可封账。
2. **M7-W5 重功能失控**：AI 审核为完整 agent 步（模态+审核步+自动修订回路），三功能塞一波必烂尾 → 护栏：一功能一票，M7-W5 开工前重新切片。
3. **证据表演化**：票多证杂，verify 沦为补截图 → 护栏：证据 = feature map 条目 + 最小关键截图，不全量；纯接线票允许 e2e 断言替代 verify 栈（处置行为可由 fixture 断言覆盖时）。

## 附录 A · 死按钮台账初值（2026-09-26 静态扫描，M7-W1 校准）

档 1 · 核心功能洞：composer 停止钮（streaming 无 handler）；project 页空态新建钮；project-new 选择仓库钮。
档 2 · 重功能未接：AI 审核（r8 §3.1 规格全）；附件 ×2 处；提及 ×2 处；新建任务添加标签；分支对话框同步+机器选择。
档 3 · 菜单/导航桩：chief 更多；schedules 卡片更多；skills 排序；account-swap；plan-dropdown 行 [待校准]；transcript 折叠。
档 4 · 文档/外链型（wontfix 移除候选）：keys-docs；res-doclink；create-agent-dialog swap；project-settings change。
档 5 · 未验证区：handler 存在但去向未追（dhead / docpane / overlays / sidebar 等 onClick 数=button 数文件群）；schedules live 接线完整性。
