# spec 15 · 新建任务无标题面与固定标签词表

> 决策记录：docs/adr/0002-新建任务无标题面与固定标签词表.md（D1–D7）。
> 本面起新建任务对话框不再 1:1 复刻 todos.dev（首个自觉背离面，ADR 0002 D7）。

## Problem Statement

新建任务对话框要求用户填标题 + 正文两个字段，并可手动创建/挑选标签。实际工作流里标题是总结正文的红米（用户写完正文还要再提炼一遍标题），自由标签则持续制造「贴不贴、贴哪个」的微决策，且标签自 #309 建起后消费面只有详情页 chips——不筛不搜，纯负担。用户要的形态：只写任务本身，标题与标签由执行 agent 回填。

## Solution

对话框收敛为单字段（正文）。标题两段式：保存时 server 落库占位标题（正文首个非空行截断 ≤50 字符），执行 agent 接单后开工前调用新增的 worker 窄工具 `set_task_meta` 用 LLM 总结回填正式标题 + 从固定词表选至多 1 个标签。标签改为固定 6 词表（bug / feature / improvement / refactor / docs / chore），随项目播种，人工创建/挑选 UI 全砍，chips 只读。对话框正文字号 13px → 14px。

## User Stories

1. As a 任务派发者，I want 新建任务只写正文一个字段，so that 创建任务的摩擦最小。
2. As a 任务派发者，I want 保存闸钉在正文非空（不再要求先起标题），so that 我不会被「标题必填」卡住。
3. As a 任务派发者，I want 正文第一行就是我的一句话任务、保存后看板卡立刻显示它（占位标题），so that 任务在 agent 接单前就可读。
4. As a 任务派发者，I want agent 接单后自动把占位标题替换成 LLM 总结的正式标题，so that 看板/详情长期可读且我不必维护标题。
5. As a 任务派发者，I want agent 同时从固定词表选一个标签贴上，so that 任务获得零人工成本的分类。
6. As a 任务派发者，I want 词表固定为 bug / feature / improvement / refactor / docs / chore，so that 分类口径稳定、可跨任务聚合。
7. As a 任务派发者，I want agent 判不出类别时不贴标签，so that 不出现为贴而贴的噪声标签。
8. As a 任务派发者，I want 回填失败不阻断任务执行（占位标题继续用），so that 元信息问题从不挡住干活。
9. As a 查看者，I want 详情页标签 chips 只读展示，so that 我看到分类但不会被引去手动维护它。
10. As a 查看者，I want 超长首行截断带省略号、卡片序号恒在，so that 占位标题撞车时仍有区分锚（已知取舍：短首行的占位态无视觉标记，ADR 0002 Premortem 第 2 条）。
11. As a 任务派发者，I want 对话框正文 14px，so that 长时间写任务不费眼。
12. As a 维护者，I want 占位标题派生逻辑单源（web fixture 面与 server 同一规则），so that fixture 与 live 行为不漂移。
13. As a 维护者，I want 固定词表常量在 shared 包单源（server 播种与 daemon prompt 注入共用），so that 词表改一处即全链路生效。

## Implementation Decisions

- **对话框（web）**：移除标题 input 与其 state、标签行与标签面板及其 state、内联新建标签表单；`onSave`/`onSaveAndStart` 签名改为 `(spec, projectId?)`（不再传 title/tagIds）；保存闸 = `spec.trim() !== ''`；autofocus 移正文 textarea；正文 `font-size` 13px → 14px；未保存闸的 dirty 判定改为只看正文；placeholder 保留五行模板族。fixture fallback 模式同步此形态（本地落卡标题 = 同一派生规则）。
- **详情页（web）**：fresh 态块移除「添加标签」行；TagChip 渲染保留（只读）。
- **占位标题派生（shared）**：`derivePlaceholderTitle(spec)` 放 shared 包单源——取首个非空行，截断 ≤50 字符，超长追加 `…`；web fixture 分支与 server createTodo 共用。
- **server 落库**：`createTodo` 在 `title` 空白时调用派生函数落占位标题；REST POST todos 与 chief `create_todo` 工具的既有显式标题路径不变（仅归一化：显式标题首尾空白 trim 后落库）。
- **固定词表（shared）**：`FIXED_TAGS` 常量（6 词，各带 name/描述/固定色）放 shared 包；server 在项目创建时播种 6 行 tag 行，启动时对存量项目按 name 幂等补齐。
- **worker 窄工具（server）**：`set_task_meta({title, tag?})`——tag 为词表 **name**（非 id，agent 无需知 id）；server 从 stepId 钉死 todoId（agent 无法越权改他任务），tag name 不在本项目词表 = 400 拒绝；title 空白 = 400；title 超 50 字符 server 侧截断兜底；成功更新走 `updateTodo` 既有面（v++ + SSE 广播，看板实时刷新）。工具定义随 worker 步 claim 载荷的 remoteTools 下发（daemon relay 零改动）。
- **prompt 注入（daemon）**：worker 步 systemPrompt 追加指令块——本任务占位标题、固定词表（name + 一句含义）、「正式开工前调用一次 `set_task_meta`：标题 ≤50 字总结任务正文；标签至多 1 个，判不出不传 tag」。调用失败仅记日志，不阻断 build。
- **i18n**：移除词条目（标签面板/表单族）清理，新增文案（若有）zh 源 + en.ts 词典同步 append（CI i18n-coverage 钉）。
- **e2e 钉扎两面同步**（改动即义务）：apps/web e2e 新建任务流 spec 改单字段路径；integration `m5-web-e2e.test.ts` 的 `.new-task-start` 等 locator 核验（按钮类名不动）。（视觉几何断言面已随 parity 工具摘除，无第三面可钉。）
- **verify-pacman feature map 同步**：新建任务流改单字段路径；`drive-tags.mjs` 的手动标签场景移除，改为断言固定词表播种（GET tags = 6 行）+ 详情页 chips 只读。

## Testing Decisions

好测试的标准：只测外部行为（保存后 todo 行的 title 值、工具调用的拒绝/接受、看板渲染），不测内部实现（state 名、私有函数）。先于实现列失败方式（仓规）：

- 空正文 → 保存/保存并开始均 disabled。
- 正文多行 → 占位标题 = 首个非空行；首行空白不产出空标题。
- 首行 >50 字符 → 截断 + `…`。
- `set_task_meta`：title 空白 400；tag 为词表外 name 400；tag 省略 = 只回填标题；重复调用 = 幂等覆盖（后写赢）。
- 播种：新项目自带 6 行 tag；存量项目启动补齐后 GET tags = 6 行且幂等（二次启动不重复插）。
- fixture 面：对话框无标题输入/无标签行；保存落卡标题 = 派生规则同 server。
- live e2e（开发期只跑相关 spec）：新建任务单字段保存 → 看板卡标题 = 首行截断。

Prior art：server vitest（`apps/server/test/todos` 族、machine-wire 测试）覆盖 createTodo/工具 handler；web e2e 覆盖对话框；verify-pacman 覆盖 live 链路。

## Out of Scope

- 按标签筛选/搜索看板（标签的筛选消费面，将来另立票。已兑现：#403 看板标签筛选条；#445 顶栏重排为仓库 + 类型双轴筛选、任务卡渲染标签 chip——ADR 0002 F4 的「看板卡不渲染标签」校准随之退役）。
- 自定义词表 UI 与详情页标签编辑（chips 只读；词表改动走 shared 常量）。
- 存量任务的标题回填（只影响新建）。
- server 侧 LLM 标题生成（ADR 0002 F1：server 无 LLM 面，重开触发见 ADR）。
- 全局字体/字重/`-webkit-font-smoothing` 调整（原站复刻 fidelity 面不动，ADR 0002 D6）。

## Further Notes

- 「只保存不派发」的任务长期挂占位标题——预期行为（ADR 0002 Premortem 第 2 条护栏：seqNum 作区分锚）。
- 与原站 todos.dev 的新建对话框 parity 永久放弃；e2e 视觉基线随本票改写后，后续背离各自立 ADR。
