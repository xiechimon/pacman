## 1. D1 定位与对既有册的影响

- 复刻对拍义务自本册起解除：02/04 册的词表对拍与像素阈值不再约束新功能；
  parity harness 保留，身份从「平价门禁」转为「回归工具」。
- `CONTEXT.md` 词汇表继续有效（产品内术语单源）；新概念命名裁决以本册后续 ADR 增补。
- 05 册 §6 后票清单转为自有 backlog，按使用痛点涌现排序（W4+）。

## 2. D2 License

Apache-2.0：MIT 的宽松度 + 专利授权条款，dev 工具生态位主流。
落地 = W1：根 `LICENSE` 全文 + `package.json` license 字段对齐。

## 3. D3 名称

保留 pacman。npm 上 `pacman` 已被占（静态站点生成器），发布形态 =
`@xiechimon/pacman` scoped 包，`npx @xiechimon/pacman` 仍是一条命令。
若未来改名：品牌槽单源（02 §5.8）一次替换全仓生效，GitHub rename 有自动重定向。

## 4. D4 公开策略

## 5. D5 工作模式

## 7. D7 研究资产

## 11. W2 发布形态决议（2026-09-25 grilling 定案）

| # | 项 | 定案 |
|---|---|---|
| W2-D1 | 包划分 | 两包：`@xiechimon/pacman`（server + 内嵌 web dist）+ `@xiechimon/pacman-cli`（执行机 daemon，现 `@pacman/cli` 改名进 scope） |
| W2-D2 | server 产物 | esbuild 单 ESM bundle（承 daemon `build.mjs` 先例）；JS 依赖全打入，native（better-sqlite3）外置 |
| W2-D3 | SQLite 驱动 | 留 better-sqlite3（Node 22/24 LTS 预编译覆盖，README 声明推荐 LTS）；node:sqlite 迁移挂观察项——drizzle 0.45.3（最新）无官方 driver，自写 sqlite-proxy 适配属独立票量级，等官方支持或痛点实锤 |
| W2-D4 | 版本/纪律 | 首发 0.1.0；engines 维持 `>=22.19`；手动 publish + wizard 走人肉位（npm login/2FA/token）；changesets 不预装（痛点触发再议） |
| W2-D5 | 验收口径 | `npx @xiechimon/pacman` 一条命令起 server（内嵌 web，首启自动建库+migrate+seed）；`npm i -g @xiechimon/pacman-cli && pacman start --api-key …`；干净环境实测全链 |

事实基线（grill 前侦察，measured）：shared = 裸 TS exports（bundle 时打入，不单独发布）；daemon 已有 bin + `build.mjs` bundle 先例；pnpm 12 发布自动替换 `catalog:`/`workspace:`；drizzle 最新版仍无 node:sqlite driver。

bin 处置：主包 bin = `pacman`（npx 主路径）；cli 包 bin 保持 `pacman`（现有文档与「添加机器」弹窗命令文案不动）。同机全局双装时后装覆盖先装——边缘场景，README 声明推荐分机部署。

## 12. W2 首发执行 runbook（wizard）

执行面：`bash scripts/publish-npm-first-release.sh`（#263 交付；#266 真人首跑的载体）。六阶段，向导只做引导、值采集与只读校验（`npm whoami` / `npm view` / `curl`），不自动 publish：

1. **npm 账号确认**——`npm whoami` 只读验证；未登录引导另终端 `npm login`，重试五巡熔断。
2. **2FA 状态**——`npmjs.com/settings/<user>/tfa`。发布门槛 = 账号 2FA 或 bypass token（npm 现行规则），本流程走前者；恢复码登录触发 72h 发布/建 token 冻结，向导显式提示。
3. **granular token（只进 env，不落盘）**——采集经 `read -rs`（fish：`read -s`）进 shell env，传递用 `npm publish --//registry.npmjs.org/:_authToken="$NPM_PUBLISH_TOKEN"` 参数形态；不写 `.env` / `.npmrc` / shell history。取舍依据（docs.npmjs.com，2026-09-25 查证，measured）：2025-11 起仅存 granular token；`NODE_AUTH_TOKEN` 非 npm 原生（靠 setup-node 写的 .npmrc 插值才生效，本向导不写盘故不用）；scope 优先限 `@xiechimon`，但首发前空 scope 选不进选择器，退路 = All Packages + 7 天过期 + 发完即删；bypass 不勾——bypass 直发 2027-01 将被 npm 移除，且账号 2FA + publish 交互 OTP 已满足发布门槛。
4. **两包 publish 顺序（人肉位）**——`@xiechimon/pacman` 先、`@xiechimon/pacman-cli` 后（互不依赖，顺序保验收链早可测）；命令打印给人肉在自己终端逐行跑。前置自检/采集失败即熔断：包名未整形（#261/#262 未落地）、`private: true`、dependencies 带 `workspace:`/`catalog:`（npm publish 会原样打进 manifest）、registry 已有非 0.1.0 版本、token 采集失败（发布命令不展示，重跑完成 Stage 3 采集后再来，不提供无 token 直发路径）。registry 已见 0.1.0 的包跳过（断点续跑）。发布后向导以 `npm view` 复核双 0.1.0。
5. **干净环境 npx 验收（W2-D5 口径）**——`mktemp -d` 隔离 HOME + 端口 8791 段自动避让（5173/8787 主仓 dev 栈、8390/8399 其它车道不动）；人肉跑 `env PORT=… HOME=… npx -y @xiechimon/pacman`，向导轮询 `/app` 200、`/api/user/me` 200、隔离 HOME 下 `.pacman/server/server.db` 落盘；随后网页建 API key → `npm i -g @xiechimon/pacman-cli` → `pacman start --api-key … --server …` enroll → 机器列表肉眼复核。localhost 探测带 `--noproxy '*'`（带代理 shell 下 curl 会把 127.0.0.1 打到代理回 503）。
6. **事后处置**——删首发 token；日常后续发布走 `npm login` + OTP，不依赖长期 token。

续跑语义：任意阶段 Ctrl-C 重跑从头（向导零落盘，token 每次重采）；脚本按 0.1.0 首发口径写死（版本校验、token 名、断点判定），后续版本首发同理改版本号复用，日常小版本直接 bump + `npm publish` + OTP。
