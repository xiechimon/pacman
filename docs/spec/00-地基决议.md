## D1 · 执行引擎：单引擎 pi + 引擎可插拔缝

**锁定。** 复刻的执行引擎（agent loop、provider 传输、会话持久化、compaction、重试）取 **pi SDK 单引擎**，不引入 Claude Agent SDK 作为并行引擎。

**理由（约束驱动）。**
1. #34 Notes 锁定「保留 OAuth 连自有 ChatGPT / Codex / Copilot / XAI 订阅」。pi 原生 `ai/src/auth/oauth/` 覆盖四家全套订阅（r4 §S2.1：`anthropic.ts` / `openai-codex.ts` / `github-copilot.ts` / `xai.ts` + pkce / device-code）。Claude Agent SDK **模型面仅 Claude 家族**（r4 §S3.1、§S3.3.1），直接不满足此锁定项——它只能作第二引擎补位，不能作唯一引擎。
2. pi 是四路中唯一「能力全开源、可精确钉版、行为可审计可 vendor」的地基，零硬缺口、无需 fork（r4 §S0.2）。
3. Claude Agent SDK 锁定最深：本体 217–234 MB/平台**闭源签名二进制**，All rights reserved + Commercial ToS + 会话数据收集条款，版本逐日追平 Claude Code、行为不可独立钉死（r4 §S3.2）。其为 todos.dev 同型场景提供的原生面（git worktree、per-agent memory、`SessionStore` 契约，r4 §S3.1）**不构成引入理由**：
   - worktree 并行与 per-agent memory 在 todos.dev 是**宿主/executor 编排层职责**（r4 §S5「各路线共担项」），#37 实测的是 executor 协议面（`tds/conv-*`、checkpoint、7 天回收），pacman 在自己的 executor 上实现同协议即可，不需复用第三方闭源二进制。
   - `SessionStore` 类可插拔持久化：pi 侧经 harness 的 `SessionRepo` 契约或宿主自建达成（r4 §S2.2、r9 §S3.1/S8 D1）。

**引擎可插拔缝（沿用 craft 的形状，不背其成本）。** craft 为「双 SDK 并架在同一产品事件面上」付出 `claude-agent.ts + pi-agent.ts + base-agent.ts + backend/ + pi-agent-server` ≈ 22.8k 行适配层（r4 §S1.2）。pacman **只借 `AgentBackend` 抽象接口形状**（provider 无关事件面 + capabilities 驱动 UI），把它落在宿主编排层与执行引擎之间——第二引擎将来是 bolt-on 而非重写。本票**不预承诺 Claude SDK 为格子**（其闭源+ToS 已被 §S3.2 否掉），缝保持 engine-agnostic。缝的具体接口签名归 `01-stack-v2.md`（#43）/ 架构册（#41）。

> **[推断] 标注**：r4 §S1.5 末「同型的是产品概念层、非进程拓扑层」、§S3.2 末「N 并行会话= N 个 ~220MB 二进制 Node 子进程」为未做移植 PoC 的定性推断。D1 的 worktree-宿主自建结论不依赖这些量化，仅依赖「worktree 是编排层职责」这一 #37 事实。

## D2 · craft-agents-oss 档位：仅参考设计、零 vendor

**锁定。** craft 在本图的角色 = **同型架构的一手证据**（r4 §S1.5 高同型行：Chief-DAG / 看板状态流 / 定时 automations / 项目 / 技能 / MCP sources / 密钥 credentials / 机器 remote / 模型服务多 LLM connection）。**不 vendor 任何 craft 包、不 build 其私有 npm 发布物。** 既成事实：`@craft-agent/*` npm registry 404（r4 §S1.3），「当库引」对 craft 不成立。

**逐块判定。**
- **Task-DAG（`task.yaml` schema + generator prompt + `TaskRunner`/Conductor）**：与 Chief 最同型（r4 §S1.5、§S1.6.3），但 #34 已锁 Chief 行为 = **黑盒逼近**（无源码证据处标 [推断]）。todos.dev 的 Chief 拆分/确认流以 #37/#41 观察为准另写；craft 的 DAG 只作**形状参考**（`NODE_KINDS` 14 种节点、`depends_on` 传参、acceptance_criteria 打分回路），不 vendor、不照搬 schema。
- **`pi-agent-server`（6.4k，craft 的 pi-out-of-process JSONL 桥）**：r9 §S7 已近读；pacman 直用 pi 稳定面（D3），不 vendor。
- **`auth/chatgpt-oauth.ts`（261 行 PKCE）**：单引擎下被 pi 原生 OAuth 覆盖（§S2.1），冗余，不取。
- **UI 组件（`packages/ui` + Electron renderer）**：见 D5，仅参考。
- **`AgentBackend` 抽象（§S1.2）**：借形状（D1），不 vendor 代码。

**vendor 逃逸口（带触发，见 §触发条款 T1）。** 若某 craft 离散件（最可能：task DAG 形状、`mcp-pool.ts`）在 #41/#43 落地时被证实「重实现成本 > Apache-2.0 vendor + divergence 债」，可在升级窗口内逐包改判为 vendor。Apache-2.0 允许（义务：保留 LICENSE/NOTICE、标注修改，并传递其 NOTICE 里的 Claude Agent SDK ToS 提示，r4 §S1.3）；商标四项硬边界（"Craft"/"Craft Agents" 文字 + logo/icon，须换名换 logo 改 bundle ID，r4 §S1.4）对 pacman 无冲突（产品名与素材本按 todos.dev 重做，归 #44）。默认档仍零 vendor。

## D3 · pi 路线层：AgentSession 稳定面为主

**锁定。** pacman 消费 pi 走 **AgentSession 稳定面**（r4 §S2.1、§S2.4.1）：其八条「有缝」项的 workaround 已由 craft 产品验证、清单现成（r4 §S2.2 = craft §S7 答案：沙箱围栏走 `BashOperations`/`BashSpawnHook` 官方缝；per-turn systemPrompt 走 `before_agent_start` inline extension；tool_call 孤儿走公开 `transformContext`；压缩竞态走宿主 `waitForCompaction` 串行化；等）。

**harness 列观察项。** pi harness（0.85.0 刚转正、experimental 消费中）提供 durable 同形物（事务性 operation state、`replay:"safe"`、suspend/中断物化、`SessionRepo` 契约，r4 §S2.1/S2.2/S3.2 末）。但 todos.dev 要的**跨会话 / 后台 / durable 编排在 pi 两条路都不现成**（r4 §S2.3：多会话并发编排、cron、memory 全在作者层）→ durable 语义由 pacman 宿主编排层自持，不外包给 harness。**故 harness 的单会话 durability 在本图不加分**，反背 experimental 风险。harness 转正后按 §触发条款 T2 重估。

## D4 · MCP：自建薄桥，pacman 自维护

**锁定。** MCP 集成走**自建薄桥**：以官方 `@modelcontextprotocol/sdk` 在 pacman 侧做 defineTool 映射，pacman 自维护，**不依赖社区 `pi-mcp-adapter`**。

**理由。** pi 核心零 MCP（r4 §S2.3、§S5）。todos.dev 的 MCP 是**双向平价面**——作 server 被 Claude Code/Codex 接入 + 作 client 消费外部 MCP（团队 server per-Agent 授权、`/api/mcp` 远程、key 级工具白名单读 11 写 13），#37 已实测（`docs/research/r3-protocol-executor.md`）。这块不能押在第三方适配器的更新节奏上；桥本身薄（工具契约映射，语义清单 r3 §S3 已定），可控可钉版。继承 01-stack「MCP 外置于 pacman」定位（r4 §S2.4.3）：本票只定归属=自建，桥的接口细节归 #41 架构册 / #43 栈册。

## D5 · UI 层地基：从零做 React，craft UI 仅交互参考

**锁定。** 前端**从零实现**：React + headless 原语（Radix 类）+ 自建 design token，对标 #36 屏级清单与 #35 抓的 todos.dev 设计 token。**不 vendor craft UI 代码**；craft UI（Electron renderer + React/Radix/cmdk）降为**组件粒度 / 交互模式参考**。

**理由。** 验收口径是「像素级 1:1 对标 **todos.dev**」（#34 Notes），目标视觉与 Craft 自家外观无关（r4 §S1.6.2、§S5 改造面）。craft UI 与其 Electron 主进程 IPC 深耦合，vendor 换到的是 divergence 债 + 形态改造，买不到像素分。**桌面兼容约束兑现**：从零做 web-native React 前端，使 macOS 桌面壳（Electron/Tauri 类，#34 Notes 留的后续意向）能包裹同一 web 前端、与 PWA 共用一套代码，不推翻 web 架构——满足 #41 须保证的桌面壳前提。组件库/样式体系/状态与数据层的逐项细锁在 #43（本票只定「从零 + craft 仅参考」这条地基边界，避免与 #43 抢 turf）。

## D6 · pin 与替换缝纪律：延续 01-stack §3

**沿用。** 全依赖**精确 patch-pin**，升级走**显式窗口**（每窗口读上游 Breaking 段再决定），接口替换缝走 01-stack §3 方法论。

**pin 面（单引擎，D1 后收窄）。** 执行引擎层 = `@earendil-works/pi-ai` / `@earendil-works/pi-coding-agent` / `@earendil-works/pi-agent-core`，钉 **0.85.1**（r4 §S2 版本核对：npm registry 实测 2026-09-19 latest，与 r9 钉版一致、r9 行号结论有效；`legacy-node20=0.74.2` 不用）。pi minor 周更自带 Breaking 段（harness 转正 / 删 legacy repo API / `ModelsStreamTransforms` 更名），升级窗口预算按 r9 §S6。**无 Claude SDK 版本追平负担**（未引入）。其余依赖（框架/存储/UI 件）逐项 pin 表在 #43 栈册。

**纪律活样本（反面）。** craft 把 Claude SDK 钉 `0.3.258`、落后当前版 19+ 版「滞后存活」（r4 §S3.2 末、§S5）——正是 patch-pin 换取行为可控的代价与收益的现成对照，写此佐证纪律方向，非建议 pacman 采同款。

## D7 · 全自研角色：兜底/对照，带触发

**降级。** 全自研引擎层从 #39 的平行选项降为**兜底/对照**，不入选默认路线。

**理由。** 选任一库化路线都免不掉自写 todos.dev 的 Chief/看板/编排/executor/托管 repo（r4 §S4.2「决策不变量」）；全自研的**增量恰是把 r9「用 pi」白赚面从零重写**——~40 家 provider wire 怪癖表 + OAuth 六件套 + session tree/compaction/重试词表 + 事件面（r4 §S4.2），人力锚点 nanobot 629 py 文件 / 4,443 commits / 2–3 核心开发者 / 7.5 个月、craft src TS ≈ 338k 行 / 8 个月（r4 §S4.2、§S1.1）——单人 + AI agents 路线（#34 Notes）下为净成本，无外部证据说明它能换回任何 todos.dev 平价分。

**触发条款（见 §触发条款 T3）。** 仅当兜底触发成立才启用，且启用形态为**逐组件自研补丁 / 只 fork 缺口件**，非整体重写。
