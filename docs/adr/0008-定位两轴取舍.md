# ADR 0008 · 定位两轴取舍——语义对齐 todos、运行对齐 Multica、不对齐其哲学

> 状态：**已裁决并生效**（2026-10-02）。
> 来源：#516 对抗性论证判决（最强反驳压测）+ #520 载体裁决。本 ADR 记「为什么这么裁」；
> 「裁成了什么」（主张句 / 判据 / 不做什么 / 诚实清单）正本 = `docs/spec/18-定位与差异化.md`，两者互引。

## Problem Statement

最强反驳（#516 票面原文）：

> Multica 开源（Go，★51,737）、可完全自托管、5 个 IM、25 个 CLI runtime、Squad / Autopilot / Gantt / 自定义状态——**而且它是活的、有人维护的**。pacman 跟它同一个骨架，凭什么不用它？

pacman 与 Multica 共享同一副骨架（看板 + agent 当经办人 + daemon 当 runtime + 自托管单数据根），而 Multica 体量大、活跃、源码开放。若差异化论证立不住，正确动作是给 Multica 贡献代码而不是维护 pacman。本 ADR 记录：为什么反驳被驳回、两轴取舍是什么、以及这个决定可能怎么死。

## 侦察事实

| # | 事实 | 出处 |
|---|---|---|
| F1 | 两边官方文档全量精读对照（todos 33 页 + Multica 41 页 + 117 条 changelog，2026-09-30）：共同骨架九条，但 todos 的语义核心（两道硬闸 / 内置 AI 审核 / 版本化方案文档）在 Multica 侧全缺——无常驻编排者、无硬闸（`in_review` 是状态不是闸门，真门是 PR）、无内置 AI 审核（教程自建 @Reviewer） | 用户知识库页「todos.dev 与 Multica 对照」 |
| F2 | pacman 的 todo phase 只能沿服务端边表流转：`apps/server/src/services/phase.ts:17` `PHASE_TRANSITIONS`，REST / MCP / chief 工具写面全过 `assertPhaseTransition`，agent 零状态自写通道；Multica 反向自认——issue 状态由 agent 自己经 CLI 显式写，「server 在 run 开始或结束时**不**翻转状态」 | 仓内源码 + Multica 官方文档 |
| F3 | 审核否决力三态：todos 内置 AI 审核但明说无否决权（「The review does not decide anything. Confirming the plan and completing the todo are still your clicks.」）；Multica 无内置（结论只是普通评论）；pacman 的 blocking verdict 直接驱动 `review→planning` 自动回流（#330），审核材料与人看同一条计算路径（#511 修掉断链） | 各家官方文档 + 仓内 #330 / #511 |
| F4 | #519 真闭环实测（2026-10-02）：闭环本体走通（#561 → PR #606 → squash 合并 → 票自动关闭），但三处欠账——AI 审核五连败（B-C9 / B-C13）、产品内合并路锁死（B-C17）、确认闸方案文档为空（B-C10）；运行面另有 #518 盘出的 25 条差距（无 runtime 对象 / 无能力广告 / 无活性判定 / 无任务级身份）。差异化主张目前只在语义面成立 | #519 交付评论 + r11 |
| F5 | Multica 是活的开源项目（v0.6.0 @2026-09-28，★51,737，自定义 license，Docker/Helm 自托管路径完整）；todos 是闭源 SaaS（self-hosted server 在公开文档里仅一句附带、无部署指南） | 知识库对照页 + `gh api repos/multica-ai/multica`（2026-09-30） |

## Decision

反驳为何被驳回（#516 判决）：反驳最大的**借来假设**是「开源 = 可以在它身上长出你要的语义」。骨架只是壳；两道闸、版本化文档、状态机漏斗是脊柱——把脊柱移植进 Multica 等于逆着它公开声明的哲学（status-first / 「Treat every run as unsandboxed」）重写它的状态机，那也是一次重写，只是放进一个你控制最少、方向跟着 51k star 与自定义 license 走的仓。star 数证明「无闸有市场」，不构成「闸无价值」的证据；对自用第一的单人，市场验证权重本来就低。

| ID | 裁决 |
|---|---|
| **D1** | **语义轴对齐 todos**：两道硬闸 + 有牙齿的 AI 审核 + 版本化方案文档 = pacman 唯一的差异化。语义轴上的机制不拿 Multica 当参考（它没有） |
| **D2** | **运行轴对齐 Multica**：runtime = 一台电脑 × 一个 CLI 工具；看板 + agent 当经办人 + daemon 当 runtime + 自托管单数据根。运行轴上的机制不自己发明（它有开源实现可读） |
| **D3** | **不对齐 Multica 哲学三条**：无硬闸、status-first、daemon 不当沙箱边界——选了等于删掉自己的差异化，做成「更弱的 Multica」 |
| **D4** | **Chief 降格**：撤出差异化支柱，降格为「闸的既定消费者」，存废由真闭环实测裁决（#516 判决 2026-10-01；早于它的 #515 两轴表述含 Chief、#521 写「差异化四件」，均以本条为准，同批更正） |
| **D5** | 判据分母 = **自用第一**：先问「我自己真用得到吗」，再问「是否差异化」；配套纪律 = 参考实现优先、不凭空造（找不到就标 `[推断]` 并降级） |
