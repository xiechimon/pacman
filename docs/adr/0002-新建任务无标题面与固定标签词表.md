# ADR 0002 · 新建任务无标题面 + agent 回填 + 固定标签词表

> 状态：**已裁决**（2026-09-29）。
> 来源：产品方向裁决——「人只负责派发（写任务正文），元信息（标题/标签）交给 AI」。本面起新建任务对话框**不再 1:1 复刻 todos.dev**（原站对话框有标题输入与手动标签）。

## Problem Statement

新建任务对话框要求用户填两个字段（标题 + 正文）并可手动贴标签。诉求：只写任务本身，标题由 agent 自动回填；标签若是自由词表则持续制造「要不要贴、贴哪个」的微决策，应固定词表并由 AI 归类。同时对话框正文字号 13px 阅读费劲，调 14px。

## 侦察事实（2026-09-29 实测，逐条出处）

| # | 事实 | 出处 |
|---|---|---|
| F1 | **server 无任何 LLM 调用面**：全仓（web/server/daemon，排除 node_modules/test）无 `generateText`/`streamText`/`messages.create`/`chat.completions`；LLM 只活在 daemon 内嵌 pi 运行时 | 全仓 grep |
| F2 | **daemon 无 todo 写回端点**：machine-client 端点集 = enroll / presence / tasks\\u200b/claim / heartbeat / tool / token / upload-urls / done / steer / stop / sync-result | `apps/daemon/src/machine-client.ts` |

## Decision

| ID | 裁决 |
|---|---|
| **D1** | 对话框**移除标题输入**，正文 textarea 升为唯一字段：保存闸 = 正文非空（原钉在标题非空），autofocus 移正文，占位提示保留五行模板（`我想要的结果：…` 族） |
| **D2** | **占位标题** = 正文首行截断 ≤50 字符，由 server 在 createTodo 落库时派生（web 不再传 title；chief `create_todo` 工具维持自填标题不变） |
| **D3** | **正式标题由执行 agent 回填**：worker 步 systemPrompt 注入「开工前调用 `set_task_meta` 回填 ≤50 字标题 + 至多 1 个标签」指令块（指令块携带当前占位标题 + 词表 name/含义）；新增 worker 窄工具 `set_task_meta({title, tag?})`——tag 为词表 **name**（agent 无需知 id），todoId 由 server 从 stepId 钉死（不进 agent 参数面，无法越权改他任务）——复用 F3 的 remoteTools relay，**不新增 HTTP 端点、不动 daemon 协议** |
| **D4** | **标签 = 固定 6 词表**：`bug` / `feature` / `improvement` / `refactor` / `docs` / `chore`，固定配色，项目创建时播种 6 行 + server 启动时补齐存量项目；每任务至多 1 个，AI 判不出不贴 |
| **D5** | **手动标签 UI 全砍**：对话框标签行 + 标签面板（#309 面）、详情页 fresh 态添加行移除；chips 只读展示保留；server `POST /api/projects/:id/tags` HTTP API 保留（播种复用 + 将来「按标签筛看板」的落点） |
| **D6** | 字体只动对话框正文 13px → 14px；字体族（Inter）、字重、全局 `-webkit-font-smoothing: antialiased`（原站复刻 fidelity 面）均不动 |
| **D7** | 本面为**首个自觉背离原站**的 UI： divergence 记录在此，后续背离须各自立 ADR |

## Premortem（假设已失败，三种最可能死因 + 护栏）

| 死因 | 护栏 |
|---|---|
| **agent 不回填**（忽略 prompt / 工具调用失败 / 模型不支持工具）→ 占位标题永存，看板停留在首行截断 | 回填失败**不阻断** build（窄工具调用包 try/catch，失败仅记日志）；占位标题本身可读；verify-pacman 验收断言「开始后标题被回填为非占位值」 |
| **占位标题撞车**（连建多个「修一下…」首行相似，看板误读） | seqNum 始终在卡片上作区分锚；agent 接单后秒级覆盖。**已知取舍**：省略号只在 >50 字符截断时出现，短首行的占位态无视觉标记（spec 15 Story 10 的张力按此裁决收口） |
| **固定词表不合用**（真实工作流想要自己的分类） | 词表是 server 单点常量，改一处即换；HTTP API 保留可编程扩展；详情页 chips 只读可随时加回编辑面（F4 证明消费面薄，加回成本低） |

## Consequences

- **正向**：新建任务从「填表」变「写一件事」；元信息质量随模型能力提升而自动改善；标签从装饰性元数据（F4）变成零人工成本的分类面。
- **负向**：#309 的手动标签 UI 面成为死代码被移除；「只保存不派发」的任务长期挂占位标题；与原站新建对话框的像素 parity 永久放弃（F6 三面钉扎随本票同步改写）。
- **重开触发**：用户要求自定义标签词表；或「保存不派发」成为常态工作流（则需 server 侧生成标题，届时重估 F1 的缝成本）。
