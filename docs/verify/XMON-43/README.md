# 看板两处 bug 独立验收（XMON-43）

验证父 issue XMON-38 的两处看板 bug 是否已修复。验收标准是用户原话，逐字如下：

1. 同一张看板内切换卡片有 bug，两张不同的看板切换就没事。
2. 看板最上端卡片被切掉一小截。

## 结论

| 验收条 | 结论 |
|---|---|
| 2. 最上端卡片被切掉一小截 | **通过**——修复前实测复现（上缘 1px 卡环被裁、露出列底色），修复后卡环在位，且与横向卡缘的读数对得上 |
| 1. 同一张看板内切换卡片异常 | **复现不出**（与修复方一致）；同时这一条**验收标准本身有歧义**，见下节 |
| 回归：两张不同看板之间切换 | **通过**——未修出新问题 |

第 1 条不是「通过」也不是「不通过」：本仓找不到「两张不同的看板」这个对应物（见
「歧义」），我能在本仓构造出的同看板换卡路径全部干净。要给它定论，需要用户补一句症状
或指出「看板」指哪个界面。

## 逐条结果

### 第 2 条：最上端卡片被切掉一小截 —— 通过

同一份探针在两个构建上各跑一遍，A 组七条从红到绿：

| 检查 | 父提交 `38c945b9` | PR `1f83107f` |
|---|---|---|
| 首卡上缘与裁切线让位（`01` / `board-overflow` / `board-repos`） | 0px → 红 | 1px → 绿 |
| 首卡上缘那一像素的颜色 | `245,245,245`（列底色，卡环被裁） | `223,223,222`（卡环在位） |
| 滚到底末卡下缘让位（`board-overflow`） | 0px → 红 | 1px → 绿 |
| 左右卡缘让位（回归） | 7.25px | 7.25px（未变） |

像素读数的取法：在首卡 border box 上缘上方 1px 处取 1 像素，与列底色参考像素（列列表
横向内边距条带上、无卡片覆盖的位置）比对——相同即「卡环被裁、露出底色」。修前那条线
画的是列底色，修后画的是卡环色，两个构建的截图（8× 左上角、4× 列顶）在
`evidence/{baseline,pr}/shots/`。

判定口径是「卡缘与裁切线之间恒有 ≥1px 让位、那一像素画的是卡环」，不是「内边距等于
1px」——钉的是可见结果，不是实现选值。

**回归面**：改动让列内容整体下移 1px、滚动高度 792→792（`01`）/ 1222→1224
（`board-overflow`），列头位置、列底边界、卡片宽度都没动。仓内与看板相关的三个 spec
在 PR 构建上全绿：`board-overflow` + `board-dnd` + `board-filter`，**33/33**
（`E2E_PORT=8481 pnpm exec playwright test board-overflow board-dnd board-filter`）。

### 第 1 条：同一张看板内切换卡片异常 —— 复现不出

先列失败方式，再逐条证伪（用 `.board-column` 的 fixture 面、`01` 与 `board-overflow`
两块看板）：

| 检查 | 路径 | 读数 |
|---|---|---|
| 连续切换卡片 | 看板 → 卡 A → 返回 → 卡 B → 返回 → 卡 A | 三次落点与「整页新开同一张卡」逐字一致；返回后看板复原 |
| 同路由换参不重挂载 | 详情 A → ⌘K → 详情 B（同看板内） | 落点与新开一致，渲染 id = 路由 id，无残留浮层 |
| 开着浮层换卡 | 详情 A 打开「更多」菜单 → ⌘K → 详情 B | 浮层不跟到下一张卡（`menus=0`） |
| 逐张扫掠 | `board-overflow` 12 张卡逐张点开再返回 | 12/12 落点与新开一致，无残留状态 |
| 全程故障面 | 上述所有页面 | console error / 页面异常 / 失败请求 **0 条** |

两个构建（修前修后）在这一组上读数相同——该 PR 只改列列表的块向内边距，本来也不可能
影响换卡路径，这一组在修前构建上同样是绿的。

「落点与新开一致」= 同一条详情 URL 在独立新页面冷加载的读数，与在应用内切过去的读数
逐字对比（`data-todo-id`、`.detail-shell` 规整化可见文本、右栏文本、路径、残留浮层计数）。

## 歧义：第 1 条的措辞在本仓没有唯一对应物

- **「两张不同的看板」在本仓找不到。** 看板面（`.board-column` 结构）只出现在 `/app`
  一条路由（探针 D2 逐路由实测：`/app/project/:id` 是「任务|文件」列表/网格面，
  `/app/project/:id/settings`、`/app/team`、`/app/schedules`、`/app/account`、
  `/app/resources/*` 都不是看板）。本仓单团队单看板，没有第二个看板可切。我用**两个
  不同数据面的看板**（`?scenario=01` 与 `?scenario=board-overflow`）代替，来回切换读数
  干净，但这是我能构造的最接近物，不等于用户说的那个。
- **「切换卡片」有多种读法**：点开另一张卡（本片覆盖）、详情页内换卡（覆盖）、同列拖拽
  换位（由仓内 `board-dnd` spec 覆盖，本次 33/33 绿）、卡片相位/列切换（未覆盖）。
- 该 PR 没有为第 1 条交付任何代码改动，所以「已消失」也无从谈起——不存在针对它的修复，
  修前修后读数一致。

要收敛：问用户「看板」指的是哪个界面（工作台 `/app`？项目页？），以及「切换卡片」是
点开另一张卡、拖拽换位、还是别的动作。
