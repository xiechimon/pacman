# Render verification: 1084 label text vs shape boxes, before and after

Method: the svg is loaded as a top-level document in Chromium and WebKit
(repo Playwright, viewport 1220x565, deviceScaleFactor 2) and dark text
pixels are measured against each shape rect. Pixel measurement instead of
eyeballing because this agent's API gateway rejects image inputs; the
measurement is stricter than an eyeball pass (exact px bounds).

Before = origin/main (git show origin/main:docs/verify/1084/hook-migration.drawio.svg),
after = this PR's re-export. Box coords are (x, y, w, h) in svg units.

Chromium, before:
  oldHook(green)     box=(0,320,480,64)     text=(8,339)-(312,366)   fits
  newHookBad(pink)   box=(540,330,560,64)   text=(548,349)-(968,376) fits
  newHookGood(green) box=(540,414,560,80)   text=(548,435)-(912,475) fits
WebKit, before: same boxes, text bboxes within 1px of the above.

Chromium, after (WebKit after: within 1px):
  oldHook(green)     box=(0,320,480,64)     text=(8,339)-(312,366)   fits, 18px bottom margin
  newHookBad(pink)   box=(540,330,560,64)   text=(548,349)-(968,376) fits, 18px bottom margin
  newHookGood(green) box=(540,414,560,80)   text=(548,435)-(912,475) fits, 19px bottom margin

Rendering is unchanged line-for-line: every authored line already fit its
wrap width, so enabling wrap moved no pixel. What changed is the exported
div geometry the gate reads — before, the three nowrap labels exported as
width-1px divs (the gate could only count words as lines: 9/19/19 lines,
FAIL x3); after, whiteSpace=wrap exports real div widths (466/546/546 px)
and the gate measures true greedy-wrapped lines (2/2/2, need 28.8px /
28.8px / 28.8px vs avail 58/58/74) against the box heights. Label text is
byte-identical (16 label texts before, 16 after, none lost, none added).

Render-path notes (measured, 2026-10-09):
- qlmanage (macOS Quick Look) is NOT a faithful renderer for these svgs:
  at -s 2000 it renders this file at ~2.59x and crops at svg x~771, cutting
  the right third of the diagram (the same happens to 1079 and 1065).
  Text slamming into that crop reads as overflow that is not in the file.
  The before/after PNGs here are Chromium renders instead.
- The drawio CLI export does not hang on this machine: /opt/homebrew/bin/
  drawio -x -f svg -e --embed-svg-images returns in seconds and a clean
  re-export of the pre-fix .drawio is byte-identical to the committed svg.
  The gate evidence therefore comes from real exports, not hand edits.
