# 创建 Agent 弹窗「模型」区：模型很多时的显示与可选性（票 XMON-40）

> 目录名用 issue identifier（本票来自 Multica 票池，无 GitHub 编号可挂），不进 `docs/verify/<GitHub 票号>/` 序列。

## 结论

**通过。** 待验分支 `b5baff11` 上，创建 Agent 弹窗的模型菜单在 46 条候选下：菜单整体落在弹窗体裁剪盒内、无行被弹窗体上沿吃掉、**上端用真实滚轮划得过去**、顶部各行用真实点击点得中。

判据轴是「**上端**」——菜单向上展开，它的顶边贴着 `.dlg-body`（`overflow-y: auto`）的可视上沿，前几行能不能被划出来、点得中，才是本票的形态。几何量（宽度、破版、滚动条）不是。

同一探针另跑一遍**改动前对照**（本轮唯一那行实现改动在运行时还原）：菜单顶越出弹窗体上沿 100px，3 行被裁没、4 行被多切，首行可见高 0/31，该位置命中的是 `.dlg-backdrop`；在顶端往上划一步都回不来，划到底再划回顶端依然不可见，真实点击 4s 超时。**探针能红**，故待验分支上的全绿不是空过。

「上边缘会不会被上面的标题方框盖住」另做了一次**遮挡判定**（用户第二轮反馈）：待验分支上菜单上沿整条都在菜单自己身上——命中测试 9/9 落在菜单内、往下滑的 4 步里被盖住的点数恒为 0、菜单上沿 248 与上方标题块下沿 240 之间留 8px；同一探针把改动前那行 `max-height` 还原后，菜单 140..440 顶到弹窗体上沿 240 之外、上沿 9/9 点被 `.dlg-backdrop` 接管。合成像素剖面同向：改动后菜单上沿有一条可分辨的浅色边框（Δ11），改动前那一段整片同色（分界：无），列表从标题框下沿直接切出来。

边界另记（与本票条件无关，见文末）：视口高 ≈396px 以下弹窗体被 `max-h` 夹住，同类症状重现。该行为改动前后一致，不是本改动引入。

## 验收标准（唯一依据）

issue 原文：「创建 Agent 时，里面的模型设置中模型太多，显示区域这边有 bug。」

判定：创建 Agent 页面的「模型设置」区域，在模型数量很多时显示正常——不溢出、不裁切、不破版、可正常浏览，且所有模型都能被正常选中。

落成可证伪的判据时，**「可正常浏览」按真实用户输入取**——真实滚轮事件（`page.mouse.wheel`）+ 真实点击，不用 `scrollIntoViewIfNeeded()`、不用直接写 `scrollTop`：这两种程序化滚动会替用户把目标滚进视野，恰好把「用户自己划不过去」这一类缺陷抹平。

## 「模型太多」这个条件是怎么来的

本机 fresh 栈上，创建弹窗的真实候选只有 **6 条**（5 个 Claude Code 槽位模型 + 「未设置模型」行）。这个规模复现不出用户报的症状——菜单高约 193px，6 条时已经贴着 192px 的封顶值，形不成「上端被裁」。

所以经**应用自己的「添加服务商」表单**（模型服务页 → 新建 → 自定义端点）写入一个 40 模型的 custom provider，候选变 46 条。数据是真用户路径写进真库的，不是在 DOM 上造假。基线（未扩量）与「太多」两个规模都测。

### 阈值是怎么定的

弹窗自然高 **348px**（大视口下实测 192..540），封顶值 `max-h-[calc(100vh-48px)]`，故视口高 < **≈396px** 时弹窗开始被夹、`.dlg-body` 才真正成为滚动盒。实测 399 / 397 / 396 干净，392 出现 4px 带动，360 出现行被切——与推算吻合。

该阈值**与模型条数无关**（封顶后菜单恒为 192px），任何条数在 360px 视口下都一样，所以它不属于本票报的「模型太多」场景；改动前在同一视口下更差，也不是本次引入。

### 上边缘合成像素剖面（`xmon-40-top-edge-pixels.mjs`）

同一列像素，窗口锚在弹窗体上沿，两版读同一段布局：

| | 改动后 | 改动前 |
|---|---|---|
| 弹窗标题块下沿 | `y=239 rgb(53,53,57)` Δ22 | `y=239 rgb(53,53,57)` Δ22 |
| 再往下 | `y=240..247 rgb(30→28,30→28,34→32)`（空隙，比两侧都略暗） | `y=240 rgb(195,229,215)` Δ176 — **直接切进文字** |
| 菜单上沿 | `y=248 rgb(39,39,42)` **Δ11**（边框线） | 名义上沿 `y=140`，上下整片 `rgb(9,9,10)`，**分界：无** |
| 菜单内部 | `y=249..251 rgb(31,31,35)` | `y=242 rgb(31,31,35)` |

即：改动后「标题块 → 空隙 → 菜单边框 → 菜单内容」四段可辨；改动前标题块下沿之下没有任何过渡，列表从裁剪线直接切出来——这才是「看着像被标题方框盖住」的来源。

边框对比度 Δ11（约 4%）确实偏淡，滚动时被切成半截的那一行上方只有这一条线做提示。这是观感问题，不是本票四条判据之一，记录在此供实现方取舍。
